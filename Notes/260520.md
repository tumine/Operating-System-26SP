磁盘调度
- SCAN 算法：类似电梯，对柱面按内—外—内进行轮询，在后续路径上有新请求时就进行处理
  - **优化了尾时延**，但平均时延表现比 SSTF 差
  - 问题：请求如果刚刚错过轮询，会造成很长的等待延迟
- CSCAN 算法：从往复轮询改为单向轮询
  - 优化平均时延
  - 即使请求有局部性，也能相比 SCAN 算法带来优化
  - 减少无谓的磁头移动：移动到边缘柱面附近时，如果路径前方没有新请求，就可以直接返回另一端柱面的第一个请求处
- LOOK/CLOOK 算法：向前看下一个请求的位置，据此决定磁头在边缘柱面附近是继续向前移动还是开启策略中新一条单向轮询路径
  - 可以减少另一端柱面的等待时长和磁头移动路程

固态硬盘：分为 SLC/MLC/TLC
- 特点
  - 异地更新，不能直接覆写硬盘中的一个特定位置，只能把新数据放在一个新的位置
  - 可靠性：floating gate 随着 program/erase 循环次数增加而不断变薄，导致其可靠性下降
    - [辅助解释](https://gemini.google.com/share/eb3d4547240e)
    - 循环次数通常在 K 级别到 10K 级别
- [组成结构](https://gemini.google.com/share/fe67698dae48)：controller、flash chips
- 读写操作
  - 粒度（Page 大小）通常为 4KB
  - 从页面读取到 SSD 寄存器，再通过总线送到 SSD 控制器，两个步骤的时延都在**微秒量级**
  - SSD 写入的时延比读取的时延更长，与 SSD 记录信息的方式相关
  - 擦除 erase：以块 block 为单位（通常是 64/128 Pages），时延在**毫秒量级**
  - 删除数据：把页面标为无效
  - 覆写/更新：把原页面标为无效，另寻空闲页面写入
- FTL(Flash Translation Layer)
  - 地址映射：*考试了解概念即可*
    - sector mapping：**以页面为粒度**，把所有逻辑页与物理页之间建立映射
      - 映射表的开销很大
    - block mapping：以 block 为粒度
      - 由于 SSD 不能就地更新，对块内进行修改时需要迁移整个 block，导致写过程复杂度很高并带来大量 program/erase 循环数
    - hybrid mapping：映射表仍然以 block 为粒度，但
      - 数据读取过程复杂度更高：定位页面的过程较冗长
    - log-structured mapping：预留日志块
    - [辅助理解](https://gemini.google.com/share/e2787fcdb45f)
  - 垃圾回收 GC(Garbage Collection)
    - 找到一个无效页面较多的块，把其中的有效页面迁移到其它位置，再擦除整个块
    - 需要考虑寿命和性能的权衡，如何在**最小化有效页面迁移数**和**保证所有块的擦除次数尽量均衡**之间找到一个合适的平衡
    - d-choice：随机选 d 个 block，在其中运用贪心算法（找有效页面最少的 block 执行 GC）
    - 冷热区分：识别被频繁更新的 block
