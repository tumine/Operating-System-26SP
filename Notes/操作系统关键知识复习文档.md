# 操作系统关键知识复习文档（1 小时版）

> 这份文档服务于一次 60 分钟的集中复习。正文按授课顺序组织，目标不是罗列名词，而是建立“问题—机制—代价—应用”的知识链。标有“易错”的内容来自对课堂 Notes 与 Slides 的交叉核对。

## 0. 先建立一张操作系统地图（0—3 分钟）

操作系统位于应用程序和硬件之间。它同时扮演三种角色：

1. **抽象提供者**：把复杂硬件包装成容易使用的对象。例如，进程让程序像在独占 CPU，虚拟地址空间让进程像在独占内存，文件把扇区/页抽象成有名字的字节序列。
2. **资源管理者**：决定哪个进程何时使用 CPU、每个进程得到多少页框、I/O 请求按什么顺序完成。
3. **保护者**：防止一个程序破坏内核或其他程序，控制文件和设备的访问权限。

整门课可以压缩成三条对应关系：

| 硬件资源 | OS 提供的主要抽象 | 核心问题 |
|---|---|---|
| CPU | 进程、线程 | 调度、通信、同步、死锁 |
| 内存 | 虚拟地址空间、页 | 地址转换、缺页、置换、分配 |
| HDD/SSD 与 I/O 设备 | 文件、目录、统一 I/O 接口 | 块分配、缓存、一致性、设备控制 |

复习任何知识点时都问四句话：它解决什么问题？依赖什么数据结构？正常流程是什么？代价或失败情形是什么？

## 1. OS 概览、双模式与系统结构（3—8 分钟）

### 1.1 中断、异常和系统调用

CPU 正在运行用户程序时，内核需要一种办法重新取得控制权：

- **硬件中断**：由设备或时钟等外部事件触发。例如磁盘完成读操作后发出中断，时钟周期性发出中断以防某进程永久占用 CPU。
- **异常**：由当前指令执行产生，例如除零、非法地址、缺页。缺页可能是可恢复异常，非法访问通常会使进程终止。
- **系统调用**：用户程序主动执行特殊指令，请求内核服务，可看作软件触发的受控陷入。

典型处理过程是：保存当前执行位置和必要寄存器 → 根据**中断向量**找到处理例程 → 切到内核态处理 → 恢复上下文并返回。

### 1.2 用户态与内核态

- 用户态只能执行普通指令，不能直接控制设备、修改页表或关闭中断。
- 内核态可以执行特权指令并访问内核数据。
- 硬件中的模式位记录当前权限。系统调用/中断进入内核态，返回用户程序时恢复用户态。

双模式不是为了让系统调用“更像函数”，而是为了建立可信边界。如果用户程序可直接操作设备或页表，一个错误程序就可能覆盖内核或其他进程的数据。

### 1.3 API、库函数与系统调用

三者的层次不同：

```text
应用代码 → API/库函数 → 系统调用接口 → 内核服务
```

例如 C 程序调用 `printf()`；标准库负责格式化和缓冲，必要时再调用 `write()` 系统调用。普通函数调用只改变程序内部控制流；系统调用还会跨越权限边界。

系统调用的参数可放在寄存器中，也可把参数写入内存块后传递其地址，或通过栈传递。参数很多时，传地址比占用大量寄存器更灵活。课件中的系统调用类型包括进程控制、文件管理、设备管理、信息维护、通信和保护。

### 1.4 操作系统结构

| 结构 | 思路 | 优点 | 代价 |
|---|---|---|---|
| 单体内核 | 大多数服务都在内核地址空间 | 调用路径短、性能好 | 模块耦合强，错误影响范围大 |
| 分层 | 上层只使用下层接口 | 便于理解、验证和调试 | 很难划出完美层次，跨层可能低效 |
| 微内核 | 内核只留最小机制，其他服务移到用户态 | 隔离好、易扩展 | 服务间消息传递和切换有开销 |
| 可加载模块 | 核心内核按需装载模块 | 兼顾性能与灵活性 | 模块仍在内核态，错误仍可能严重 |
| 混合结构 | 组合多种结构 | 适应真实系统需求 | 设计更复杂 |

“机制与策略分离”是理解设计题的钥匙：机制回答“系统能做什么”，策略回答“这一次怎样选择”。时钟中断是机制，时间片长度是策略；上下文切换是机制，调度算法是策略。

## 2. 进程与线程（8—15 分钟）

### 2.1 程序、进程与地址空间

**程序**是静态代码和数据，**进程**是程序的一次执行。一个可执行文件可产生多个进程，一个进程也可用 `exec()` 改为执行另一个程序。

典型用户地址空间从低地址到高地址包含：

```text
代码与只读常量 | 已初始化数据 | BSS | 堆 → …… ← 栈
```

- 代码段保存机器指令，通常只读。
- 数据段保存已初始化的全局/静态变量。
- BSS 保存未初始化或初始化为 0 的全局/静态变量；可执行文件通常只记录其大小，不保存一大片零。
- 堆由动态内存分配器管理，常向高地址增长。
- 栈保存函数参数、返回地址、保存的寄存器和局部变量，通常向低地址增长。

### 2.2 PCB：内核眼中的进程

内核不能只保存一段程序代码，还必须用**进程控制块 PCB**记录：

- 进程状态；
- 程序计数器和 CPU 寄存器；
- 调度信息，如优先级和队列指针；
- 内存管理信息，如页表基址；
- 记账信息，如 CPU 时间和进程号；
- I/O 状态，如打开文件和待完成 I/O。

PCB 是进程被暂停后仍能继续执行的依据。**上下文切换**就是保存旧进程的 CPU 上下文到 PCB，再从新进程 PCB 恢复上下文。切换期间 CPU 没有推进用户任务，因此切换越频繁，管理开销越大；但完全不切换又会损害响应性和公平性。

### 2.3 五状态模型

```text
新建 ──接纳──> 就绪 ──调度──> 运行 ──结束──> 终止
                  ▲          │
                  │          ├──时间片到/被抢占──┐
                  │          ▼                  │
                  └──事件完成── 等待/阻塞 <──等待 I/O/事件
```

- **就绪**：万事俱备，只差 CPU。
- **等待/阻塞**：即使给 CPU 也不能继续，必须等待 I/O 或事件。

易错：就绪不是“正在运行”，阻塞也不是“排队等 CPU”。

### 2.4 `fork`、`exec`、`exit`、`wait`

以 shell 启动命令为例：

1. shell 调用 `fork()` 创建子进程。父进程中返回子 PID，子进程中返回 0；失败返回负值。
2. 子进程调用 `exec*()`，用新程序的代码、数据、堆和栈替换自己的用户地址空间。`exec` 成功后不会返回旧程序。
3. 父进程可调用 `wait()/waitpid()` 阻塞，等待并回收子进程的退出状态。
4. 子进程调用 `exit()` 或从 `main` 返回，释放大部分资源并留下退出信息，通知父进程。

现代 `fork()` 通常采用**写时复制 COW**：父子先共享只读标记的物理页，某一方写入时才复制该页。这避免先复制全部内存、紧接着又被 `exec()` 覆盖。

- **僵尸进程**：已经终止，但父进程尚未 `wait`，所以退出信息和最小进程记录仍保留。它不能被再次“杀死”，应由父进程回收；父进程退出后通常由系统收养者回收。
- **孤儿进程**：父进程先结束、子进程仍在运行。孤儿与僵尸描述的是不同维度。

### 2.5 线程为什么“轻”

同一进程内的线程共享代码、全局数据、堆、地址空间和打开文件；每个线程独有程序计数器、寄存器、栈和线程状态。因此线程创建/切换和通信通常比进程便宜，但一个线程写坏共享内存会影响整个进程。

多对一模型无法让多个用户线程同时在多核上执行；一对一并行性好但内核线程开销较多；多对多在多个用户线程和若干内核线程之间复用。

Amdahl 定律说明加核的上限。若程序中可并行比例为 `P`，使用 `N` 个处理器，理想加速比为：

$$
S(N)=\frac{1}{(1-P)+P/N}
$$

即使 `N` 无限大，加速比也不会超过 $1/(1-P)$。串行部分决定最终上限。

## 3. IPC、同步与死锁（15—26 分钟）

### 3.1 两类进程间通信

| 方式 | 工作方式 | 优点 | 需要注意 |
|---|---|---|---|
| 共享内存 | 多个进程映射同一片物理内存 | 建立后按普通内存访问，数据量大时快 | 读写冲突必须另行同步 |
| 消息传递 | 通过 `send/receive` 和内核队列交换消息 | 隔离清晰，易扩展到网络 | 系统调用、复制和上下文切换可能增加开销 |

消息通信还要确定：直接按进程名还是通过 mailbox 间接通信；发送/接收是否阻塞；缓冲区为零、有界还是无界。零容量通信常要求发送者和接收者会合；有界缓冲区满时发送者必须等待。

### 3.2 竞争条件与临界区

`count++` 并非一条不可分割动作，而可能是：从内存读入寄存器 → 加一 → 写回内存。两个线程交错执行时，两次加一可能只得到一次效果。**执行结果依赖并发指令的交错顺序**，就是竞争条件。

访问共享对象的代码片段称为临界区。一个正确的通用临界区方案应满足：

1. **互斥**：同一时刻最多一个进程处于相关临界区。
2. **不依赖速度和 CPU 数**：不能靠“另一个进程大概还没运行到这里”保证正确。
3. **进步**：临界区空闲时，只有想进入的进程参与选择，不能被无关进程永久拖住。
4. **有限等待**：请求进入后，其他进程插队次数存在上界，避免饥饿。

关闭中断只适合内核极短的局部场景，且单个 CPU 关闭中断不能阻止其他 CPU。`test-and-set`、`compare-and-swap` 等硬件原子指令可实现锁。

- **自旋锁**反复检查锁，等待时消耗 CPU，适合多核上极短临界区。
- **阻塞锁**把等待者挂入队列，释放 CPU，适合等待较长的情形，但睡眠和唤醒也有开销。
- 内存屏障保证屏障前后的内存操作不会以破坏同步语义的方式重排。

### 3.3 信号量

信号量是带有原子操作和等待队列的同步对象：

- `wait(S)` / `P(S)` / `down(S)`：尝试取得一个资源；无资源则阻塞。
- `signal(S)` / `V(S)` / `up(S)`：归还资源，并可能唤醒一个等待者。

二进制信号量可表达互斥，计数信号量可表达资源数量或事件数量。

#### 有界生产者—消费者

设缓冲区有 `N` 个槽：`mutex=1`、`empty=N`、`full=0`。

```c
// producer
wait(empty);          // 先确保有空槽，不能拿着 mutex 睡眠等空槽
wait(mutex);
insert_item();
signal(mutex);
signal(full);         // 宣布多了一个可消费项

// consumer
wait(full);           // 先确保有数据
wait(mutex);
remove_item();
signal(mutex);
signal(empty);        // 宣布多了一个空槽
```

若生产者先取得 `mutex` 再等待 `empty`，缓冲区满时生产者会拿锁睡眠，消费者又拿不到锁来取数据，形成死锁。

#### 读者—写者与哲学家

- 读者—写者：允许多个读者并发，但写者必须独占。偏向读者会饿死写者，偏向写者又可能增大读延迟，公平方案需增加排队或 turnstile。
- 哲学家：每人先拿一只筷子再等另一只会形成循环等待。可用一次性取得两只、限制同时竞争人数、规定统一取锁顺序等方法破坏死锁条件。

### 3.4 死锁

死锁是若干进程都在等待只有集合中其他进程才能释放的资源。四个必要条件必须同时成立：

1. 互斥；
2. 占有并等待；
3. 不可抢占；
4. 循环等待。

四类处理方法：

| 方法 | 思路 | 代价/风险 |
|---|---|---|
| 预防 | 设计规则破坏至少一个必要条件，如统一资源申请顺序 | 资源利用率或编程灵活性下降 |
| 避免 | 每次分配前判断分配后是否仍安全，如银行家算法 | 需预知最大需求，持续计算安全性 |
| 检测与恢复 | 允许死锁，周期检测后终止/回滚/抢占 | 检测和恢复有成本，可能损失工作 |
| 忽略 | 假设死锁少见，由用户或系统重启进程 | 不适合高可靠场景 |

**资源分配图**中，进程到资源是请求边，资源到进程是分配边。每类资源只有一个实例时，有环等价于死锁；存在多个实例时，有环只是可能死锁，必须进一步计算。

多实例检测可令 `Work=Available`：反复寻找尚未结束且 `Request[i] <= Work` 的进程，假设它完成并令 `Work += Allocation[i]`。最后仍无法标记的进程属于死锁集合。

银行家算法判断的是**安全状态**：是否存在一个安全序列，使每个进程的剩余最大需求都能依次得到满足。非安全状态意味着未来可能死锁，但不等于当前已经死锁。

## 4. CPU 调度（26—35 分钟）

### 4.1 为什么调度

进程在 CPU burst 与 I/O wait 之间交替。一个进程等待 I/O 时，让另一个就绪进程运行能提高 CPU 利用率；交互程序还要求尽快获得第一次响应。

对进程 `i`：

$$
\begin{aligned}
T_i &= C_i-A_i &&\text{周转时间：完成时刻减到达时刻}\\
W_i &= T_i-B_i &&\text{等待时间：周转时间减 CPU burst 总长}\\
R_i &= S_i-A_i &&\text{响应时间：第一次运行时刻减到达时刻}
\end{aligned}
$$

其中 `A` 是到达时刻，`C` 是完成时刻，`B` 是 CPU 运行总时长，`S` 是第一次运行时刻。优化平均值不能保证尾时延；公平性、吞吐量和响应性也可能互相冲突。

### 4.2 常见算法

| 算法 | 选择规则 | 优点 | 典型问题 |
|---|---|---|---|
| FCFS | 最早到达先运行 | 简单、开销小 | 长任务阻挡短任务，产生护航效应 |
| SJF | burst 最短者先运行 | 已知 burst 时平均等待时间最小 | 很难准确知道下一次 burst，长任务可能饥饿 |
| SRTF | 剩余时间最短，可抢占 | 比非抢占 SJF 更有利于短任务 | 切换更多，仍需预测 burst |
| RR | 每次运行一个时间片 `q` | 响应公平，适合分时系统 | `q` 太小切换多，太大退化为 FCFS |
| 优先级 | 最高优先级先运行 | 表达任务重要性 | 低优先级可能饥饿；可用老化缓解 |
| 多级队列 | 不同类别固定在不同队列 | 可为不同类别采用不同策略 | 分类静态，低队列可能长期等待 |
| 多级反馈队列 | 根据运行行为升降队列 | 兼顾短交互任务和长任务 | 参数多、实现复杂 |

SJF 可用指数平均预测下一次 CPU burst：

$$
\tau_{n+1}=\alpha t_n+(1-\alpha)\tau_n,\quad 0\leq\alpha\leq1
$$

`α` 越大越重视最近一次实际值，响应变化快但波动也大。

### 4.3 甘特图例题

三个进程同时在 `t=0` 到达，burst 分别为 `P1=6`、`P2=2`、`P3=4`。

- FCFS（输入顺序 P1、P2、P3）：`P1[0,6] P2[6,8] P3[8,12]`，等待时间为 `0,6,8`，平均 `14/3`。
- SJF：`P2[0,2] P3[2,6] P1[6,12]`，等待时间为 `0,2,6`（按执行顺序），平均 `8/3`。
- RR，`q=2`：`P1 P2 P3 P1 P3 P1`；完成时刻分别为 `12,4,10`，等待时间分别为 `6,2,6`，平均 `14/3`。

做题顺序：先标到达事件 → 按算法画完整时间轴 → 读出每个完成/首次运行时刻 → 最后代公式。抢占算法在“新进程到达”和“时间片到”处都要重新决策。

### 4.4 实时与多处理器调度

- **RM（Rate-Monotonic）**：静态优先级，周期越短、到达频率越高，优先级越高。
- **EDF（Earliest Deadline First）**：动态优先级，绝对截止期最近者先执行。

实时调度不仅取决于算法，还受中断时延和分派时延影响。多处理器调度还要平衡负载与缓存亲和性：迁移任务可均衡 CPU，却可能丢失热缓存，并在 NUMA 系统中增加远程内存开销。

Linux CFS 用虚拟运行时间 `vruntime` 近似公平：`vruntime` 小的任务优先；nice 值影响其增长速度，任务通常按 `vruntime` 保存在红黑树中。

## 5. 内存管理与虚拟内存（35—46 分钟）

### 5.1 堆分配与碎片

`malloc()` 是库接口，分配器从进程堆中寻找合适空闲块，必要时再通过系统调用扩展可用地址空间。`free()` 将块归还给分配器，不保证立刻归还物理内存或缩小进程。

- **内部碎片**：已经分配的块内部没有被请求者使用的空间。
- **外部碎片**：总空闲空间足够，却分散成小洞，无法满足较大连续请求。

首次适配快；最佳适配寻找最小可用洞但搜索成本高且可能留下细碎小洞；分离空闲链表按大小分类；伙伴系统按 2 的幂拆分和合并，便于快速得到连续页框；Slab 为内核同类小对象缓存已初始化对象，减少碎片和初始化开销。

### 5.2 分页地址转换

若页大小为 $2^d$ 字节，则虚拟地址低 `d` 位是页内偏移，其余高位是虚拟页号：

$$
p=\left\lfloor VA/2^d\right\rfloor,\qquad offset=VA\bmod 2^d
$$

查页表得到页框号 `f` 后：

$$PA=f\times 2^d+offset$$

例：页大小 4 KiB，虚拟地址 `0x12345`。低 12 位为偏移 `0x345`，虚拟页号为 `0x12`。若页表项映射到页框 `0x2A`，物理地址为 `0x2A345`。

页表项通常还包含 valid/present 位、读写执行权限、访问位和修改位。页表不仅做地址映射，也做保护和页面状态记录。

单级页表会为巨大且稀疏的虚拟空间保留大量条目。多级页表把页号继续拆分，只在对应区域实际使用时创建下层页表。代价是一次 TLB 未命中的转换可能访问多级页表。

### 5.3 TLB

TLB 是页表项的高速缓存，键近似为“进程地址空间标识 + 虚拟页号”，值为页框号和权限。TLB 命中时无需走内存中的页表。

若 TLB 查询时间为 `ε`、一次内存访问为 `m`、命中率为 `h`，单级页表且忽略缺页时：

$$EAT=h(\varepsilon+m)+(1-h)(\varepsilon+2m)$$

未命中比命中多一次页表内存访问。多级页表未命中的代价还会更高。

### 5.4 请求调页与缺页处理

请求调页只在页面真正被访问时将其放入物理内存。合法但不驻留的页面被访问时产生缺页：

1. 硬件发现 present/valid 状态不满足，陷入内核。
2. 内核判断地址是否合法；非法则终止进程。
3. 找空闲页框；没有则选择牺牲页。脏页要先写回外存，干净页可直接丢弃。
4. 从可执行文件、映射文件或交换区读入所需页面。
5. 更新页表和 TLB，使指令重新执行。

若普通访存时间为 `ma`、缺页完整服务时间为 `pf`、缺页率为 `p`：

$$EAT=(1-p)\,ma+p\,pf$$

由于 `pf` 常比 `ma` 大多个数量级，缺页率必须极低。

易错：虚拟空间上限不简单等于“物理内存 + 交换区”。它还受地址位宽、进程布局、系统策略和 overcommit 影响；物理内存与 swap 主要限制可承载的驻留/后备内容。

### 5.5 页面置换

| 算法 | 换出对象 | 特点 |
|---|---|---|
| OPT | 未来最久不会再用的页 | 理论最优，用作比较基准，无法在线实现 |
| FIFO | 最早进入内存的页 | 简单，但可能出现 Belady 异常 |
| LRU | 过去最久没有被访问的页 | 利用时间局部性，精确实现成本高 |
| Second Chance/Clock | FIFO 基础上检查访问位 | 用硬件访问位近似 LRU |
| LFU/MFU | 累计访问次数最少/最多 | 需要计数，旧历史可能误导决策 |

Clock 算法检查指针所指页面：访问位为 0 就置换；为 1 则清零并移动指针，给它第二次机会。若加入修改位，通常优先淘汰“未访问且未修改”的页，避免写回。

易错：LRU 是 **Least Recently Used**，不是“访问总次数最少”；后者是 LFU。LRU 换出的是“距离上次访问最久”的页。

FIFO 的 Belady 异常指增加页框反而增加缺页次数；OPT 和 LRU 具有栈包含性质，不会出现该异常。

### 5.6 页框分配与抖动

- 全局置换可从其他进程取页，整体弹性大，但进程性能相互影响。
- 局部置换只在本进程页框中选择，隔离较好，但分配不足时难以自救。

进程得到的页框少于其当前局部性所需时，会不断缺页、换入、换出，CPU 大部分时间在等分页 I/O，这就是**抖动**。系统若只看到 CPU 利用率下降并继续增加进程，反而会恶化抖动。

工作集 $WSS_i$ 是最近窗口内进程 `i` 使用的不同页面集合大小。若 $\sum WSS_i$ 超过物理页框数，系统应降低多道程序度或调整分配。缺页率控制则为每个进程设上下界：过高则增页框，过低则回收部分页框。

内存映射文件 `mmap()` 把文件区间映射为虚拟页。首次访问触发缺页并从文件读入，以后像普通内存访问；多个进程还能把同一文件页映射到各自地址空间，减少重复复制与系统调用。

## 6. 外存、RAID 与 I/O（46—52 分钟）

### 6.1 HDD 与磁盘调度

HDD 的盘面分磁道和扇区，相同半径的磁道组成柱面。访问时间主要包括寻道时间、旋转延迟和数据传输时间。顺序访问通常比大量随机小访问快，因为可摊薄机械定位成本。

磁盘调度题通常用磁头移动的柱面总数近似寻道开销：

- FCFS：按请求到达顺序，公平简单但可能来回大幅移动。
- SSTF：每次服务最近请求，平均移动量常较小，但远处请求可能饥饿。
- SCAN：像电梯一样来回扫描，尾延迟比 SSTF 稳定。
- C-SCAN：只在一个方向服务，到端点后快速返回，使等待更均匀。
- LOOK/C-LOOK：只移动到该方向最后一个实际请求，不必到物理边界。

做题必须先确认：初始磁头位置、初始方向、磁道边界，以及“回程是否计入移动距离”。不同约定会产生不同数值。

### 6.2 SSD、FTL 与 GC

NAND Flash 以页读/编程，以包含许多页的块擦除；已写页不能直接原地覆盖。更新通常写到新页并把旧页标无效。因此控制器中的 FTL 要完成：

- 逻辑块地址到物理页映射；
- 垃圾回收：搬走某块中的有效页，再擦除整块；
- 磨损均衡：避免少数块过早达到擦写寿命；
- 可能还包括坏块管理。

GC 在“搬迁尽量少的有效页”和“磨损尽量均匀”之间权衡。写放大是主机写入少量数据、SSD 内部却因迁移和回收产生更多写入。

### 6.3 RAID 与纠删码

假设 `N` 块等容量磁盘、每块容量为 `D`：

| 级别 | 可用容量（典型） | 容错 | 关键特征 |
|---|---:|---:|---|
| RAID 0 | `ND` | 0 块 | 条带化提高并行吞吐，无冗余 |
| RAID 1 | 约 `ND/2` | 每镜像组可坏 1 块 | 镜像，读可并行，容量成本高 |
| RAID 4 | `(N-1)D` | 1 块 | 专用校验盘，更新时可能成为瓶颈 |
| RAID 5 | `(N-1)D` | 1 块 | 校验条带分散到各盘 |
| RAID 6 | `(N-2)D` | 2 块 | 两份独立校验，写入和计算更贵 |

小更新的 read-modify-write：读旧数据和旧校验，计算新校验，再写新数据和新校验。RAID 5 解决了 RAID 4 的专用校验盘带宽瓶颈，但没有减少校验更新本身。纠删码把 `k` 个数据块编码为额外 `m` 块，通常可容忍任意 `m` 块丢失，比多副本更节省容量，但编码和修复更复杂。

### 6.4 I/O 控制与内核 I/O 子系统

- **轮询**：CPU 反复读设备状态寄存器；设备很快或等待极短时合理，慢设备会浪费 CPU。
- **中断驱动**：CPU 发出请求后做其他工作，设备完成时中断通知。
- **DMA**：CPU 设置内存地址、长度和方向，DMA 控制器在设备与内存之间搬运一大块数据，完成后通常只中断一次。

设备驱动把具体控制器细节封装在统一接口后。内核 I/O 子系统还提供调度、缓冲、缓存、假脱机、错误处理和访问保护。同步 I/O 在操作完成前阻塞调用者；异步 I/O 先返回，完成后再通知。

## 7. 文件系统、FAT32 与 Ext（52—60 分钟）

### 7.1 文件、目录和一次读取

文件系统定义两件事：**设备上放什么、放在哪里（layout）**，以及**怎样访问和修改（operations）**。

文件由内容和属性组成。属性可包括大小、类型、所有者、权限、时间戳和数据块位置。目录本身也是文件，其中的目录项把名字映射到文件元数据（如 inode 号）。路径 `/a/b.txt` 必须从根目录开始逐级查找 `a` 和 `b.txt`。

一次典型读取：

1. `open(path, flags)` 逐级解析目录，检查权限，在内核打开文件表建立条目，返回整数**文件描述符 fd**。
2. `read(fd, user_buf, n)` 通过 fd 找到打开文件状态和当前偏移，再通过文件元数据定位数据块。
3. 数据不在缓存时，驱动/控制器从设备读到内核缓存；内核再向用户缓冲区复制，更新文件偏移。
4. `close(fd)` 释放本进程对打开文件条目的引用；最后一个引用消失后才回收相应内核对象。

易错：POSIX `open()` 返回 `int fd`；C 标准库 `fopen()` 返回 `FILE *`。`FILE` 结构还维护用户态缓冲和库状态，不能把二者混为一谈。

### 7.2 文件块分配

| 分配方式 | 元数据 | 优点 | 缺点 |
|---|---|---|---|
| 连续分配 | 起始块 + 长度 | 顺序和随机访问都快，元数据少 | 外部碎片，文件增长困难 |
| 链式分配 | 每块指向下一块 | 易增长、无外部碎片 | 随机访问慢，指针占空间且损坏影响后续链 |
| FAT | 集中表中记录下一块 | 链信息可缓存，遍历比散布指针方便 | FAT 可能很大，随机访问仍沿链 |
| inode/索引分配 | 索引节点保存块号 | 直接支持随机访问，适应大小文件 | 间接块占空间，大文件需多级访问 |

inode 常同时含若干直接块指针和一级、二级、三级间接指针。若块大小为 `B`、块号占 `a` 字节，则每个间接块可存 `K=B/a` 个地址。若有 `d` 个直接指针及一至三级间接指针，理论最大数据量约为：

$$B(d+K+K^2+K^3)$$

计算题先算每个间接块能放多少地址，再分层计数；不要把存地址的间接块误算成文件数据块。

文件系统还必须管理空闲空间，例如用位图记录每个块是否空闲。磁盘可划为多个分区，每个分区可独立建立文件系统；传统 MBR 保存引导代码和分区表。文件系统自身的关键参数不能硬编码，通常保存在 FAT 的 boot sector 或 Ext 的 superblock 等结构中。

### 7.3 FAT32

典型 FAT32 分区包含 boot sector、FSINFO、保留扇区、两份 FAT 和根目录/数据区。FAT 项记录一个簇的下一簇号或特殊状态；“32”指表项宽度，实际可用地址位少于完整 32 位。

- 传统短文件名使用 8.3 格式；长文件名通过普通目录项附近的若干特殊 LFN 目录项保存，并用校验关联。
- 多字节字段按规定字节序解释；课件通过目录项强调了大端/小端概念。
- 追加文件：找到链尾；末簇不够则分配新簇、更新 FAT 链和空闲空间信息，再更新目录项大小。
- 删除文件：把目录项标为删除、释放 FAT 链和空闲状态。数据区通常不会立即覆写，所以在尚未复用时可能恢复。
- 安全删除需要覆写原数据或使用介质支持的可靠擦除机制；只删目录项不等于数据消失。

FAT 简单且兼容性好，但大 FAT 的缓存成本、沿链随机访问和一致性维护都是限制。

### 7.4 Ext2/3 的块组、链接与缓存

Ext 把文件系统分为多个块组，每组通常含 superblock 副本、组描述信息 GDT、块位图、inode 位图、inode 表和数据块。分组能让相关 inode 与数据靠近，缩短定位并限制单一区域损坏的影响；关键元数据副本提高可恢复性。

- **硬链接**是另一个目录项，指向同一个 inode；共享同一内容和链接计数。只有链接计数为 0 且无打开引用时，文件数据才可真正回收。硬链接通常不能跨文件系统。
- **符号链接**是独立文件，内容是目标路径；目标删除后链接可以悬空，也可跨文件系统。
- `.` 指向当前目录，`..` 指向父目录，它们影响目录链接计数。

内核缓存数据页、目录项和 inode，显著减少设备访问。预读根据顺序访问局部性提前读取后续块；随机访问时错误预读会浪费 I/O 和缓存。延迟写提高合并和调度机会，但断电前尚未落盘的数据可能丢失。

### 7.5 日志与 VFS

一次文件系统操作可能要修改目录项、inode、位图和数据块。若只完成一部分就断电，布局会不一致。日志把相关修改视为事务：先写日志记录，再写一个可识别的提交记录，之后把修改 checkpoint 到正式位置。恢复时只重放已完整提交的事务，忽略不完整事务。

常见模式的权衡：

- **data journaling**：数据和元数据都进日志，一致性强，写放大最大。
- **ordered metadata journaling**：只记录元数据，但保证对应数据先写到正式位置，再提交元数据日志。
- **writeback metadata journaling**：只记录元数据，且数据与日志顺序约束较弱，性能较好但崩溃后可能看到旧数据。

VFS 在系统调用与具体文件系统之间提供统一对象和操作接口。`open/read/write` 通过 VFS 分派到 Ext、FAT 等实现。若某文件系统不支持某操作，内核应返回相应错误；不能把“返回给用户一个空指针”当作通用语义。

## 8. 高频易错点速查

1. 系统调用不是普通库函数；库函数可能完全在用户态完成，也可能包装一个或多个系统调用。
2. 中断/异常进入内核态；缺页可以是正常的按需调页事件，不必然是段错误。
3. 就绪进程在等 CPU，阻塞进程在等事件。
4. `exec()` 不创建新进程；它替换当前进程的用户程序。
5. 僵尸已经结束，孤儿可能仍在运行。
6. 互斥只保证“不能同时进入”，不自动保证进步、公平和无死锁。
7. 信号量操作顺序会决定是否死锁；不要拿着 `mutex` 等 `empty/full`。
8. 非安全状态不等于已经死锁；多实例资源图有环也不一定死锁。
9. 等待时间不包含实际运行时间；响应时间只看第一次获得 CPU。
10. LRU 是最久未使用，不是使用次数最少。
11. TLB 缓存地址转换，cache 缓存数据/指令；两者相关但不是同一个概念。
12. 页变多时 FIFO 仍可能缺页更多，这就是 Belady 异常。
13. SSD 没有寻道延迟，不代表写入没有代价；擦除、GC 和写放大会影响性能与寿命。
14. RAID 不是备份；它主要应对设备故障，不能防止误删、软件破坏或所有盘同时损坏。
15. `open()` 返回 fd，`fopen()` 返回 `FILE *`。
16. 删除文件通常先删除名字/索引并回收空间，不一定立即抹除数据。
17. 硬链接共享 inode，符号链接保存路径。
18. journaling 主要保证崩溃后一致恢复，不等于所有最新用户数据都已持久化。

## 9. 12 道自测题

先遮住答案，要求每题在 30 秒内说出关键词。

### 题目

1. 为什么既需要系统调用，也需要时钟中断？
2. PCB 中至少应保存哪四类信息？
3. `fork()` 后紧接 `exec()` 时，COW 为什么有用？
4. “临界区互斥”之外，一个正确方案还要满足哪些要求？
5. 有界缓冲区中为什么必须先 `wait(empty)` 再 `wait(mutex)`？
6. 死锁的四个必要条件是什么？非安全状态是否等于死锁？
7. 已知到达、首次运行、完成和 burst，怎样算响应、周转、等待时间？
8. 4 KiB 页中虚拟地址低多少位是页内偏移？地址 `0x12345` 的偏移是多少？
9. LRU 与 LFU 的选择依据有何不同？哪个会出现 Belady 异常？
10. SSD 更新一页为什么可能引发远多于一页的内部写入？
11. 连续分配、FAT、inode 各自最突出的优缺点是什么？
12. 硬链接、符号链接和日志分别解决什么问题？

### 参考答案

1. 系统调用让程序主动请求内核服务；时钟中断让内核即使面对不主动让出 CPU 的程序也能周期性重获控制权。
2. CPU 执行上下文、状态/调度信息、内存管理信息、记账与 I/O 信息；答出其中四类即可。
3. 父子先共享物理页，只在写入时复制，避免把马上会被 `exec()` 覆盖的全部地址空间预先复制一遍。
4. 不依赖相对速度和 CPU 数、进步、有限等待；连同互斥共四项。
5. 若缓冲区已满，生产者拿着 `mutex` 等空槽，消费者就无法进入临界区取走数据并产生空槽，构成死锁。
6. 互斥、占有并等待、不可抢占、循环等待。非安全只是无法保证存在安全完成序列，不等于当前已经死锁。
7. 响应 = 首次运行 - 到达；周转 = 完成 - 到达；等待 = 周转 - burst 总长。
8. 4 KiB = $2^{12}$，低 12 位；偏移为 `0x345`。
9. LRU 选距离上次使用最久的页，LFU 选累计使用次数最少的页。FIFO 可能出现 Belady 异常，LRU 不会。
10. Flash 不能原地覆盖且以块擦除；FTL 可能搬迁块中有效页、擦除块并重写，引发 GC 和写放大。
11. 连续分配访问快但碎片/增长困难；FAT 易增长且链集中管理但随机访问仍慢、表可能很大；inode 随机访问好、兼顾大小文件但间接块有空间和访问开销。
12. 硬链接让多个目录项共享同一 inode；符号链接用路径引用另一文件；日志让多块更新在崩溃后可按事务恢复一致性。
