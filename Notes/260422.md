短作业优先的进程调度算法（SJF）：允许抢占/不允许抢占
- 允许抢占：在进程结束时、新进程到达时判断是否进行上下文切换
- 短作业优先算法不考虑时钟中断（即可能存在一个进程占有足够长的 CPU 时间片）
- 问题：如何知道下一个任务的 CPU 突发时间？
  - 指数平均：把最新信息和历史信息进行加权预测下一个任务的突发事件 $\tau_{n+1}=\alpha t_n+(1-\alpha)\tau_n$
  - $\alpha$ 代表预测结果对上一个 CPU 突发时间的敏感性
  - 敏感度过高，性能预测可能波动过大

Round-Robin 调度：希望对每个进程都有一定的服务保障
- 给每个任务一个固定的时间片用于执行；若时间片用完后任务仍未完成，就回收 CPU 资源分配给下一个任务
- Round-Robin 的平均等待时间、平均完成时间、上下文切换次数都比短作业优先调度的表现更差
- 保证响应性能：每个任务都能以一定速度推进
- 问题：需要设置一个合适的时间片长度
  - 前台/后台应用
  - 优先级高的任务/优先级低的任务
  - 时间片越短，响应越快，但上下文切换频率越高
  - 时间片过短时，可能会带来不必要的上下文切换
  - 时间片过长时，就会退化为 FCFS
  - **准则**：让 80% 的 CPU 突发时间比设置的时间片长度短

优先级调度：调度器基于任务优先级选择下一个执行的任务
- SJF、FCFS 本质上都是一种优先级调度
- 如何定义优先级？
  - 需要考虑一些任务可能出现无限期等待
  - 解决思想：优先级的 Aging（动态优先级设置）
  - 随着等待时间延长，不断提高一个任务的优先级

多级队列调度：每个优先级都采用一个任务队列，单个队列可采用不同的调度方案
- 特点：每个任务的优先级是**静态**的
- 高优先级的任务需要具备**运行时间短**、重要度高的特点，否则低优先级的任务可能**长时间等待**
- 高优先级的任务需要能**抢占**低优先级的任务，避免**优先级反转**

多级反馈队列：加入**自适应调节**
- 最通用，也最复杂的调度算法
- 可以动态调节一个任务的优先级
- 需要考虑的问题
  - 需要设置多少个队列？
  - 每个队列采用什么算法？
  - 优先级切换时机？
  - 切换优先级时，可以跳级换入还是必须在相邻优先级之间切换？

实时系统调度
- 硬实时：必须在一个固定的时限之前完成关键任务
- 软实时：给关键的任务一个更高的优先级
- 不仅是算法层面的问题，也是系统实现层面的问题（中断时延、分派时延等因素影响）
- （**重要**）两种实时调度算法
  - 速率单调
    - 假定进程在到达时间周期 $p$ 内请求的处理时间为 $t$
    - 优先级分配：速率正比；速率（到达的频率）越高，优先级越高
    - 需要允许抢占，当速率更高的进程到来时，抢占当前正在执行的低速率进程
    - 问题：简单的速率单调不能保证调度总运行时间占比不足 100% 所有进程
