### 课件第 1 章：OS 概览
计算机系统的组织
- 用户：计算需求的发出者，包括人类或其它计算机系统
- 硬件：CPU、内存、I/O 设备等，提供最基础的计算资源
- 应用程序：连接用户需求与底层计算资源
- 操作系统：在不同的应用程序与用户之间，控制协调硬件资源的使用情况

操作系统的定位和目标
- 介于用户与硬件资源之间
- 执行用户程序，简化用户问题的解决流程
- 高效利用计算机的硬件资源
- 在使用的便捷性和高效性间作出权衡

从**系统角度**来看，操作系统
- 控制程序：控制程序的运行，阻止错误产生和对于计算机的非法使用
- 资源分配者：管理所有硬件资源，在出现资源的冲突请求时**确保资源的使用高效公平**

从用户视角看，操作系统
- 对于 PC 用户，易用性、性能表现优异
- 对于共享计算机：最大化资源利用率
- 对于专用系统：权衡本地硬件资源和服务端的共享资源使用
- 可移动计算设备：可用性、续航能力
- 嵌入式计算设备：无 UI

**操作系统定义**
- 内核：计算机上始终运行的程序
- 系统程序：操作系统除内核以外的部分，协助用户管理系统
- 应用程序：用户根据其需求自行安装

多道程序系统：操作系统最重要的一个方面
- 通过合理组织作业 job（代码、数据）
- 所有作业最初都放入作业池，其中的一个子集调入内存准备执行
- 操作系统通过作业调度 job scheduling 选择一个作业在 CPU 上运行
- 当前作业需要等待（例如 I/O）时，操作系统切换到另一个作业

多任务处理 multitasking：用户在每个作业运行时都能与其进行实时交互
- **要求**：响应时间少于 1 秒
- CPU 调度：多个作业在同一时间都处于就绪状态
- 交换技术 swapping：新到进程不能放入内存中，把暂时不运行的进程换出到外存
- 虚拟内存：允许进程在没有完全装入内存的情况下也能执行

中断驱动机制
- 硬件中断：由外部硬件发起
- 软件中断：异常或陷阱，软件错误/请求 OS 服务/其它进程问题
- 由中断服务例程 interrupt service routine 处理中断

双模式运行：用户模式、内核模式
- 硬件层面支持模式位 mode bit
- 模式位的作用：区分当前执行的代码类型
- 部分指令只能在内核模式下运行
- 系统调用执行时切换到内核模式，执行完毕返回前切换回用户模式

系统调用 system calls
- 存放位置：**操作系统内核**
- 特性：原子性 primitive（不可再分，直接与硬件或内核交互），重要性，基础性
- 分类：进程管理、文件系统、内存管理、安全、设备管理
- 与库函数调用 library function calls
  - **系统调用更底层**，对程序员不友好 not programmer-friendly
  - 库函数封装在库文件 library file 中，调用某个库函数的过程：“程序→库文件中库函数→操作系统内核中系统调用”

进程 process 与程序 program
- 进程是程序的执行实例，是动态的
- 多个进程可以执行相同的程序，一个进程在生命周期中可以执行多个程序
- 进程有局部状态 local states，指示现在执行哪行代码，运行在哪个 CPU 核上，使用哪些资源等
- 查看和管理进程的常用命令：`ps`、`top`

shell：为每个运行的命令创建子进程

进程间关系：树形结构

进程特性
- 进程需要获取系统资源以完成任务 task；进程终止 termination 时系统回收所有可复用的资源（CPU、内存、I/O、文件、初始化数据）
- 单线程进程有**一个**程序计数器指示下一条指令，多线程进程对于每个线程都有一个程序计数器
- 系统中有各种用户进程、OS 进程**并发运行**

操作系统在进程管理中的任务
- 创建和删除用户进程
- 挂起 suspend、恢复 resume 进程
- 提供进程同步机制 process synchronization
- 提供进程通信机制 process communication
- 提供死锁处理机制 deadlock handling

存储器层次结构
- 程序启动时从外存调入内存，开始执行时由 CPU 从内存中获取指令和数据
- CPU 中存放正在被 CPU 执行的进程的指令和数据，内存中存放等待被调度的就绪进程，外存中存放非活跃、挂起、未加载的进程

内存管理目的和行为
- 根本目标：优化 **CPU 利用率**和计算机对用户的**响应速度**
- 追踪内存各个部分的使用情况、使用者
- 决定哪部分进程需要换入/换出内存
- 根据程序需求动态分配/回收内存空间

文件系统的两面性
- 静态：**存储设计**，决定数据如何在磁盘上排布，需要用到哪些元数据
- 动态：对外提供对于已存储数据的各种**操作**

文件系统管理
- 文件组织在目录中
- **访问控制**：决定谁可以访问什么内容
- 操作系统活动：创建/删除文件和目录，提供操作文件和目录的原语 primitives，将文件映射到次级存储，将文件备份到非易失存储介质

大容量存储管理
- 计算机运行速度取决于磁盘子系统和其调度算法的速率
- 操作系统活动：空闲空间管理，存储分配，磁盘调度
- 三级存储（光盘、磁带）不追求速度，但仍然必须被操作系统或应用程序管理

内核数据结构
- 链表：单链表，双链表，循环链表
- 栈：用于函数调用
- 队列：用于作业调度
- 树：二叉树，二叉搜索树，平衡二叉搜索树
- 哈希函数：处理哈希冲突，可以利用哈希函数建立**哈希表存放数据**
- 位图 bitmap：指示磁盘块可用性

### 课件第 2 章：OS 服务与结构
操作系统基本职能
- 提供程序**执行环境**
- 对程序和用户提供服务（UI、命令行等）
- 服务的常见目的（类别）：用户便利性，系统效率

面向用户便利性的操作系统服务
- 程序执行：加载到内存，运行，终止执行（正常结束/异常结束）
- I/O 操作：帮助用户间接进行 I/O 操作，**提高效率**并**保护**系统
- 文件系统操作：主要服务包括读写文件/目录，创建删除文件/目录，查找指定文件，罗列文件信息，权限管理（允许/拒绝访问）
- 进程间通信（同一计算机上，通过网络在不同计算机间）：共享内存、消息传递
- 错误检测：错误来自 CPU、内存、I/O 设备、用户程序，错误处理需要确保计算结果正确、一致，必要时终止系统或引发错误的进程
- 用户界面 UI：**CLI**（shell 命令）、**批处理**（shell 脚本）、**GUI**
  - CLI：输入文本命令来与系统交互，可以内置在操作系统中或作为特殊应用程序
    - 实现命令的两种方式：**内置命令**，**外部命令**
    - 内置命令：shell 跳转到内部代码的对应部分并发出系统调用
    - 内置命令数量决定 CLI 程序大小
    - 外部命令：shell 把命令当成文件名到系统路径中查找，加载到内存中并执行
    - 外部命令扩展性好
  - GUI：由图标指示文件、程序、各种操作
  - UI 选择：CLI 更高效、易于处理**重复性任务**；GUI 对**用户友好**；UI 设计和实现不是操作系统的直接功能（不同的 UI 对应相同的操作系统内核）

面向系统效率的操作系统服务
- 资源分配：可能采用特殊的分配算法（CPU 调度等）
- 记账 accounting：记录每个用户使用哪些资源，用于计费和使用情况统计（重新配置系统，提高效率）
- 安全保护：可控地访问系统资源，通过用户验证获得访问权限，防止外部 I/O 设备非法访问

系统调用：操作系统提供给应用程序的编程接口
- 实现语言：多数采用 **C/C++** 编写，少量需要**直接访问硬件**的低级任务采用**汇编语言**编写
- 不足：单个程序的系统调用次数可能极高，且每个操作系统的系统调用名称不同

应用程序编程接口 Application Programming Interface(API)
- 相比系统调用的优点：易用，**可移植**
- 常见 API 集合：**Win32 API**, **POSIX API**（适用于基于 UNIX 的系统，Linux、Mac OS 等）, **Java API**
- 调用方式：操作系统提供的代码库

系统调用接口 system call interface
- 应用程序调用 API 时，系统调用接口拦截该调用，转换为操作系统内核调用
- 系统调用拥有一个编号，系统调用接口维护**调用号到对应系统调用的映射表**
- 好处：调用者只需要知道 API 调用格式，不需要关系具体执行细节

系统调用传参
- 原因：需要提供更多具体信息和参数
- **传递方法**：寄存器、块/表（内存中，其首地址存入寄存器传递给操作系统）、栈

系统调用的主要类别：进程控制，文件操作，设备操作，信息维护（系统运行数据、调试、时间日期管理），通信，保护（设置权限、允许/拒绝资源访问）

操作系统结构
- MS-DOS
  - 在小空间中提供尽可能多的功能
  - 没有划分内核态和用户态（缺乏芯片硬件支持）
  - 特定功能组件未划分成模块（文件系统模块、进程管理模块、内存管理模块、设备驱动模块等）
  - 接口与功能层级未充分分离：应用程序可以绕过操作系统执行硬件读写，操作系统无法阻止程序直接访问底层
- UNIX
  - 操作系统组成：系统程序+内核
  - 内核包含系统调用接口、物理硬件之间的**所有内容**（文件系统、CPU 调度算法、内存管理等）
  - 单体结构：所有功能集合进同一个层级
  - **有利于性能**，但**难以实现和维护**
- 分层法
  - 结构特点：操作系统**分为若干层**，上一层建立在下一层的基础上
  - 底层 layer 0 是硬件，顶层 layer N 是用户界面
  - 实现方式：**上层只能调用下层**提供的接口
  - 优点：易于构建和调试
  - 缺点：层级划分困难（下层不能依赖上层的功能），**不利于跨层操作**（参数传递、上下文切换）
- 微内核
  - 特点：将功能尽可能从内核移到用户空间，**内核只负责进程管理、内存管理、通信**
  - 微内核的主要功能：采用**消息传递**实现进程间通信 IPC；各个组件（位于用户空间）之间的交流必须通过微内核
  - 优点
    - 易于**扩展**微内核，所有新增服务都位于用户空间
    - 易于将操作系统**移植到新硬件架构上**
    - **更可靠安全**（运行在内核模式的代码更少）
  - 缺点：不同服务之间必须通过微内核的消息传递实现，**双模式切换、上下文切换**开销大
- 模块化：**最佳方法**
  - 动态链接：**内核只保留基础核心组件**，在启动时或运行时动态链接额外服务（设备驱动程序、文件系统）
  - 相比分层系统，模块化设计更灵活（任何模块都可以调用其它模块）
  - 相比微内核，模块化设计更高效（**模块都位于内核中**，通信不需要通过内核的消息传递）
- 混合系统
  - 目的：综合解决系统性能、安全性、可用性需求

操作系统设计
- 首要问题：设计目标和规范
  - 设计需求受到硬件环境、系统类型的影响
  - 用户侧目标：易用，易学，可靠，安全，高速
  - 系统侧目标：易设计，易实现，易维护，灵活，可靠，不出错，高效
- **核心原则**：机制 mechanism, How 与策略 policy, What 分离
  - 例子：CPU 保护的计时器机制，与计时器设定的时长策略分离
  - 例子：作业调度的优先级机制，与程序的优先级配置策略分离
  - 好处：可以在不改变机制的情况下**根据实际情况随时调整策略**，适应不同运行环境和需求

操作系统实现
- 混合语言策略：内核主体使用 C 编写，底层硬件交互部分使用汇编语言编写，系统程序使用 C/C++ 和脚本语言编写
  - 优点：**编写速度更快**，易于**理解和调试**，易于**移植**到其它硬件
  - 缺点：**运行速度更慢**（相比汇编语言），**存储空间占用更多**

### 课件第 3 章：进程操作
**程序**：一个可执行文件

程序生成过程
- 预处理器：展开条件编译、宏、头文件
- 编译器：语法检查和分析，生成汇编代码 `.s`
- 优化器：在编译器编译过程中优化代码
- 汇编器：利用汇编代码 `.s` 生成目标文件 `.o`
- 链接器：将所有目标文件和库文件 libraries 链接起来
  - 库文件：分为静态库文件 `.a`、动态库文件 `.so/.dll`
  - 静态库文件**直接与目标文件链接**生成可执行文件
  - 动态库文件在链接时只**记录引用标记**，在运行时再将 `.so` 文件加载到内存中并与程序建立连接
- 多文件编译
  - 只允许有一个主函数
  - 将各个文件依次编译进目标文件，再将它们链接起来成为最终的可执行文件

**进程**：执行中的程序
- **程序加载进内存后**，成为进程
- 一个处理器上任意时刻只能运行一个进程
- 多个进程可以共享一段程序
- **一个进程可以是另一段程序的运行环境**（如 JVM 进程执行 Java 代码）

内存中进程结构
- 代码段：位于**内存空间最低端**，存储程序的机器代码和指令
- 数据段：存储全局变量、静态变量
- 堆：用于动态内存分配
- 栈：位于**内存空间最高端**，存储临时数据（函数传参、返回地址、局部变量）
- 程序计数器和寄存器：进程上下文的一部分，记录程序当前状态

进程状态
- 新建 new：进程被创建
- 运行中 running：进程指令正在 CPU 中执行
- 等待 waiting：进程正等待某个事件发生
- 就绪 ready：进程**已具备运行条件**，**等待分配**到某个处理器
- 终止 terminated：进程**执行完毕**

进程控制块 PCB
- 内容
  - 进程状态、程序计数器
  - CPU 寄存器：**进程挂起时** CPU 内部寄存器（通用寄存器、栈指针、CPU 状态字）的状态快照
  - CPU 调度信息：记录进程的**调度优先级**，指向**进程所在调度队列**的指针等调度参数，供 OS 调度器决定下一个运行的进程
  - 内存管理信息：记录分配给进程的内存情况（内存范围，页表指针等）
  - I/O 状态信息：记录进程占有的 I/O 设备和**打开文件列表**
  - 记账信息：记录进程的**资源使用情况**（CPU 时间、启动后经过的时间、占用内存），进程 ID 等
- 管理方式：双向链表
- 作用：进程发起系统调用时，**保存 CPU 寄存器**、校验系统调用权限、根据具体系统调用读写 PCB（如给子进程复制父进程 PCB 中内容，根据 I/O 请求修改 PCB 状态为等待，获取进程 PID）

进程操作
- 进程识别：`getpid()`，返回发起系统调用的进程 PID
- 进程创建：`fork()`
  - 内核启动时创建第一个进程 `init`，由 `init` 创建更多进程
  - 进程树：`pstree` 命令查看
  - LInux 系统中，一个进程终止时，其子进程过继给 `init`
  - 允许子进程在没有父终端的情况下仍能继续运行（而不是关闭父终端的同时终止子进程）
  - **父子进程关系**
    - 资源共享：父子进程共享所有资源/子进程共享父进程的部分资源/父子进程不共享资源
    - 执行：父子进程并发执行/父进程等待子进程终止
    - 地址空间：子进程是父进程的副本/子进程执行一个新程序
  - 子进程从程序中 **`fork()` 返回处**开始执行，该 `fork()` 给子进程的返回值为 0
  - 在单个 CPU 核情形下，**父子进程的执行顺序取决于操作系统调度算法**
  - `fork()` 行为
    - 复制父进程在内存中的所有结构（代码段、数据段、堆、栈）、PCB 中的**打开文件表**、程序计数器
    - 重置 PCB 记账信息（运行时间）
- 进程执行：`exec*()`（如 `execl()`），完全替换进程当前执行的程序（替换失败时仍然继续执行当前程序）
  - 丢弃原程序运行时的**进程内存结构**、PCB 中 **CPU 寄存器快照**，保留 PCB 中的记账信息、CPU 调度信息等
  - 强制子进程先于父进程执行：在 `fork()` 后父进程新指令之前使用 `wait()`
  - 当**某一个**子进程终止时，`wait()` **返回该子进程 PID**
  - 如果某个进程没有子进程/没有正在运行 running 的子进程，`wait()` 不起作用
  - 等待特定进程：`waitpid()`，同时可以检测子进程的各种状态变化

系统内存布局：内核空间内存+用户空间内存
- 内核空间内存：**内核数据结构**、**内核代码**、**设备驱动程序**
- 用户空间内存：进程内存、进程程序代码

程序执行时间：用户时间+系统时间
- 系统上下文切换（访问内核硬件）给进程带来额外执行时间
- 通过**减少系统调用的发起次数**，可以减少进程执行时间
- 系统调用对应用程序的性能有重大影响
- 通过按块读取而不是按字节读取，可以提高系统级性能

内核中进程组织：任务链表（双向链表）
- `fork()` 行为：在父进程节点的子进程链表域添加子进程，在任务链表中新增复制子进程节点，修改子进程节点的父进程域、记账信息等

打开文件表
- **索引 0, 1, 2 分别对应 stdin, stdout, stderr**
- 索引 3 以后对应程序执行过程中打开的文件

终止子进程：`exit()`
- 释放大部分内核空间内存（PCB、打开文件表）
- 释放用户空间内存
- 在任务链表中**仍然保留子进程条目**（记账信息、退出状态码），称为僵尸进程
- 内核向父进程发出 SIGCHLD 信号指示子进程终止

信号
- 本质：软件中断
- 类型：用户空间信号、内核/CPU 信号

僵尸进程回收：父进程使用**信号处理程序**（**调用 `wait()` 时**内核设置，默认不响应）处理 SIGCHLD 信号
- 接收并移除 SIGCHLD 信号
- 销毁对应的子进程
- 父进程**移除 SIGCHLD 信号处理程序**
- 信号处理过程仍然位于 `wait()` 系统调用过程中，**没有执行父进程自身的程序**
- 父进程调用 `wait()` 在子进程终止之后，并不会影响子进程的回收
- 父进程未调用 `wait()` 并终止：子进程过继给 `init`，**`init` 定期发起 `wait()` 系统调用以回收僵尸进程**

僵尸进程产生场景
- 进程显式调用 `exit()`
- 进程从 main 函数返回
- 进程异常终止，**内核代替进程调用 `exit()`**

### 课件第 4 章：线程
应用侧使用线程的原因
- 应用程序的实现方式：进程，内部包含**多个控制线程**处理不同子任务
- 进程创建更耗时，需要大量新资源
- **多个子任务之间可以共享大量数据**

系统侧使用线程的原因
- 多核系统，每个核同一时间只能执行一个进程
- 提高效率：给每个核分配一个任务，实现真并行

并发/并行：**单核并发，多核并行**

进程-线程结构
- **每个线程拥有自己的寄存器、栈空间**；所有线程共享代码段、数据段、堆、**打开文件表**
- 线程生命周期：执行单一函数（**线程函数**），期间可以调用其它函数或发起系统调用

多线程优点
- 利于多任务处理和响应能力：对交互式应用程序尤其重要
- 易于共享数据：通过全局变量或堆空间，但**需要考虑同步、互斥问题**
- 经济性：创建线程需要的资源更少、时间更短，进程上下文切换开销大
- 可扩展性：不同线程可以分配到不同 CPU 核上并行执行

多线程编程挑战
- 划分独立的并发任务
- 负载均衡
- 数据拆分：程序处理的数据需要合理分割给不同线程
- 数据依赖：同步、互斥问题
- 测试和调试：多线程程序的执行顺序通常不确定，**难以重现问题**

线程实现方式：用户级线程（用户空间中实现）、内核级线程（内核支持和管理）

线程模型
- 多对一：所有用户级线程映射到同一个内核级进程
  - 优点：易于内核实现
  - 缺点：单线程发起的阻塞式系统调用会**阻塞所有线程**
- 一对一：每个用户级线程映射到一个内核进程/线程结构
  - 优点：阻塞只局限在发起系统调用的线程，保证**高并发度**
  - 缺点：内核线程创建能力有限，**系统不能创建过多线程**
- 多对多：多个用户级线程映射到数量相等或更少的内核级线程
  - 优点：可以按需创建**大量线程**，同时保证**高并发度**

多线程执行策略：异步/同步
- 异步线程：父子线程并发执行，**很少有数据共享**
- 同步线程：**分支-合并策略 fork-join strategy**，父线程等待所有子线程终止 join 后再执行，存在**大量数据共享**

线程操作
- 创建：`pthread_create()`，给定一个**线程函数**
- 终止：`pthread_exit()`
- 回收：`pthread_join()`，类似 `wait()`

线程传参
- 按址传递时，新线程可以修改主线程的局部变量值

多线程创建：使用 for 循环 `pthread_join()` 等待每个子线程运行完成

线程函数返回值
- 通过 `pthread_exit()` 传递，主线程 `pthread_join()` 中指定接收变量指针
- 如果需要把结果写入内存、传递指针，需要**确保指针指向进程的数据段**（而不是本线程的局部变量）

隐式线程
- 背景：应用程序通常包含**数千个线程**，使用显式线程难以保证程序正确性（竞态条件、死锁）
- 解决方案：把线程创建和管理的任务交给编译器和运行时库

多线程服务器的问题：一次性线程带来大量创建开销，无法创建不限量线程

线程池
- 思想：预先创建一批线程，新工作出现时分配线程，工作完成时回到线程池，无可用线程时等待
- 优势：线程分配的**响应时间更短**，线程池可**限制线程最大数量**

OpenMP
- 提供**共享内存环境**中的并行编程支持
- 属性：**编译器指令和 API** 的集合
- 功能：在高级语言代码中标识并行区域；遇到 OpenMP 指令时**创建与 CPU 核心数量相等的线程**

多线程进程的 `fork()`：复制所有线程/只复制调用 `fork()` 的线程

多线程进程的 `exec()`：替换所有线程的上下文

多线程进程的信号处理：传递给导致信号产生的线程/传递给每一个线程/传递给某些特定线程/传递给专门的信号处理线程

线程取消
- 定义：在线程完成任务之前提前终止该线程
- 方法
  - 异步取消 asynchronous，立即终止目标线程
  - 延迟取消 deferred：设置**标志位**，线程在运行过程中动态检查自己是否应该被取消
- 函数实现：`pthread_cancel()`，向线程发送**取消请求**（不是强制取消）
- 线程默认取消模式：延迟取消 deferred
- 线程取消点配置：`pthread_testcancel()`

线程局部存储 Thread Local Storage (TLS)
- 定位：线程级的“全局变量”，类似 static 变量，**在线程生命周期内**（跨函数调用）**始终可见**
- 每个线程的 TLS 各不相同，多个线程对同一个 TLS 变量名的访问结果不同

### 课件第 5 章：进程通信
进程间关系
- 独立：进程彼此不受干扰
- 协作：进程之间相互影响（只要共享数据，就是协作进程）

协作进程的必要性
- 信息共享：在进程之间共享文件
- **加速计算**：并行执行不同的子任务
- **模块化**：将系统功能划分到独立的进程中
- **便利性**：单用户可以**利用多进程执行多任务**

进程间通信 InterProcess Communication (IPC)
- 目的：在进程间交换数据
- 逻辑模型抽象：生产者-消费者模型，生产者生产信息，消费者处理信息
- 系统实现模型抽象：共享内存模型、消息传递模型

共享内存模型
- 思想：建立共享内存区域，进程通过对共享区域的**内存读写**进行信息传递
- 主要结构：生产者进程—缓冲区队列—消费者进程
  - 生产者在队列已满时挂起，由消费者在操作缓冲区时唤醒
  - 消费者在队列为空时挂起，由生产者在操作缓冲区时唤醒
  - 缓冲区用循环队列实现，最多容纳 BUFSIZE-1 个条目
- 优点：速度快

消息传递模型
- 思想：通过**内核介入**，在进程之间传递消息
- 过程：建立信道—传递信息
- 主要实现问题
  - 命名 naming：直接/间接通信
    - 直接通信：`send/receive` 时指定对方进程
      - 通信链路在进程间**自动建立**
      - 每条链路固定对应一对进程
      - **每对进程之间只有一条通信链路**
      - 劣势：**不利于模块化**（难以复用到其它环境）
    - 间接通信：`send/receive` 时指定邮箱
      - 只有两个进程共享某个邮箱时才建立通信链路
      - 一对进程之间可能有多条通信链路
      - 一条通信链路可能关联多个进程
      - 问题：邮箱链接到多个进程时如何确定哪个进程获取消息？谁拥有邮箱？
        - 限制链路只能关联一对进程；只允许一个进程接收消息；**系统算法**将消息分配给进程
        - 邮箱归进程所有，生命周期绑定或可传递所有权；邮箱归 OS 所有，需要**提供完整系统调用**（创建、收发、删除）
  - 同步 synchronization：阻塞/非阻塞
    - 阻塞发送/阻塞接收，非阻塞发送/非阻塞接收（接收得到有效消息或空值）
    - 会合 rendezvous：收发端都阻塞，**在传递消息时必须同步**
    - 缓冲 buffering：**至少一端非阻塞时**，系统需提供缓冲区（阻塞接收不代表任何时刻接收端都在等待）
  - 缓冲区：零容量/有限容量/无限容量
    - 零容量：发送端必须等待接收端
    - 有限容量：如果缓冲区满，发送端必须等待
    - 无限容量：发送端始终不需要等待
- 优点：在分布式系统中更容易实现

套接字 sockets
- 定位：网络通信端点，收发端（**进程级别**，不是主机级别）各需要一个套接字
- 识别：IP 地址+端口号
  - 低于 1024 的端口号都用于标准服务（telnet-23, FTP-21, HTTP-80）
- 服务端：在特定端口监听客户端连接请求
- 每个套接字连接都由源 IP、源端口、目标 IP、目标端口唯一确定
- 回环地址：用于**同一台主机上**的进程通信

管道
- 定位：进程间通信通道
- 普通管道：仅用于**父子进程间通信**，单工（区分写端/读端），通信结束后销毁
  - UNIX 管道：**视为文件**，可被子进程继承以建立通信
  - 管道的文件描述符：`fd[0]` 为读端，`fd[1]` 为写端
  - `fork()` 后，父子进程各自关闭读/写端（避免自产自销），建立单向通信
- 命名管道
  - 要求：不需要父子进程关系（但**位于相同机器**），**可有多个写端**，必须**显式删除**，半双工
- 操作系统通常为管道提供内置同步、互斥机制，**允许多个进程同时读写管道**

竞态条件
- **定义**：**程序执行执行结果依赖于共享资源访问的顺序**
- 常见场景：资源共享、多核多线程（共享进程全局变量和动态分配内存）

互斥
- 定义：一次只有一个进程可以访问共享对象
- 内核层级实现方式：非抢占内核易设计，且易于实现互斥；抢占式内核响应更快，**更适合实时编程**
- 负面代价：**阻碍并行计算性能**

临界区 critical section
- 定义：**访问共享对象的代码段**
- 临界区前有进入区 section entry，之后有退出区 section exit
- 要求：**尽可能紧凑**，避免阻塞其它进程或被其它进程阻塞；一个临界区可以访问多个共享对象
- **进入区和退出区**是互斥实现的保证

进入区和退出区的实现
- 要求
  - 互斥：一次只能有一个进程进入临界区
  - 解决方案不依赖临界区占用时长
  - **进展** progress：未在其余区域运行的进程才能参与进入临界区的选择
  - 有限等待：没有进程为了进入临界区而无限期等待
- 实现挑战：操作必须是原子的
- 方案：禁止中断
  - 思想：类似非抢占内核，在进入临界区前禁止上下文切换
  - 效果：进程在临界区中执行时没有其它进程可执行
  - 实现需求：操作系统提供禁用/启用中断的系统调用
  - 评估：逻辑上正确，但**不适用于多处理器系统**，且**严重降低并发能力**
- 方案：互斥锁
  - 思想：必须持锁进入临界区
  - 实现：获取和释放锁的过程必须是原子的，**借助硬件指令实现**
  - 缺陷：忙等消耗 CPU 资源（称为**自旋锁**）
  - 适用场景：多处理器，锁只会**短时间持有**
- 方案：严格轮换法
  - 思想：使用一个共享对象让两个进程交替进入临界区
  - 缺点：忙等效率低下，进程无法连续进入临界区，**违反进展原则**
- 方案：Peterson 方案
  - 思想：把优先权递给对方，在本方获得优先权或**对方不需要进入临界区** interested=0 时进入临界区

信号量方案
- 属性：一种数据类型
- 分类：二进制信号量、计数信号量
- **原子操作**：`down()`，尝试**占用**信号量对应的资源；`up()`，**释放**信号量对应的资源
  - **只有信号量值为 0 时，`down()` 才会阻塞当前进程**
- 解决忙等：将进程送入**信号量附带的队列**，在有进程调用 `up()` 时从队列中唤醒一个进程
- 解决原子操作：禁用中断
  - 原子操作：包含的所有指令要么全部未执行，要么全部执行

死锁问题
- **条件**：**互斥，占有并等待，非抢占，循环等待**
- 描述
  - 资源-分配图，每个进程节点的出边是等待边，入边是占有边
  - 矩阵描述：总资源向量 E、可用资源向量 A、分配矩阵 C（行代表进程号，列代表资源号）、请求矩阵 R
- 避免死锁：**银行家算法**，判断每个新请求是否导向非安全状态
  - 安全状态：存在一种运行序列使得所有进程的需求都可被满足
  - 非安全状态：不存在任何序列使得所有进程的需求都可被满足
- 忽略死锁：死锁**发生频率低**，**预防和检测成本高**

**哲学家就餐问题**
- 解决方案：丢弃叉子的预设，通过标记哲学家状态为 EATING 等效拿起两把叉子
- 自己用餐完成后，唤醒左右邻居用餐
- 互斥锁 `mutex` 用于**保证原子操作**，哲学家信号量 `s[i]` 用于允许哲学家进入临界区

**生产者-消费者问题**：互斥（一个二进制信号量 `mutex`），同步（两个计数信号量 `full=0, empty=N`，分别指示占用和未占用的缓冲区槽位数量）
- 同步：协调进程执行顺序，确保产生有意义的输出
- **在进入临界区时，互斥锁上锁必须在所有计数信号量改变之后**，即**不能带着互斥锁进入睡眠**
- 离开临界区时，互斥锁与计数信号量的改变顺序理论上没有必然要求，但**先释放互斥锁更好**

**读者-写者问题**
- 场景设定：读者可以并发读取，但读写操作互斥
- 读者优先共享对象使用：`db` 用于**保护读写互斥**，`mutex` 用于保证原子操作，`read_count` 变量用于追踪并发读者数量
- 读写公平：**增加 `queue` 用于排队**，拿到 `queue` 后才能对 `db` 上锁
- 写者优先：在读者优先方案基础上，增加 `writer_count` 统计写者人数，增加 `read_try` 用于保证有新写者时没有读者可以获得数据库的锁

### 课件第 6 章：进程调度
进程等待策略：可中断/不可中断
- 可中断：waiting 期间可以接收和处理外部发送的信号并切换进程状态
- 不可中断：waiting 期间忽略大部分外部信号直到获得所需资源

进程调度定义：让所有处在就绪状态的进程依次切换到运行状态

触发进程调度的事件：新进程创建，已有进程终止，进程等待 I/O，进程完成 I/O

上下文切换：**备份旧进程的所有寄存器值**（放入进程 PCB），加载新进程的上下文
- 新进程**原本可能位于外存中**，带来较大上下文开销

调度算法**衡量标准**：CPU 利用率、吞吐率（单位时间内完成的进程数量）、**周转时间**（进程从提交到完成的时间）、等待时间（进程在等待队列中的总时间）、**响应时间**（进程从提交到**第一次被响应**的时间）

调度算法：离线（预知所有提交到系统的进程情况）/**在线**
- FCFS
  - 调度效果**对进程输入顺序敏感**，考虑“长进程—若干短进程”情形
  - 平均等待时间经常较长
- SJF (Shortest Job First)
  - 允许抢占/不允许抢占
  - 允许抢占情形下平均等待时间、平均周转时间更短，但**上下文切换次数更多**
  - 理论最优，但不能应用
  - 近似解决方案：**指数平均**，**假设下一个 CPU 突发时间长度与之前的突发时间长度相近**（$\tau_{n+1}=\alpha t_n+(1-\alpha)\tau_n$，$\tau$ 是预测值，$t$ 是真实 CPU 突发时间，$\alpha$ 是权重系数）
- RR (Round Robin)：**当前采纳的方案之一**
  - 思想：每个进程执行一个时间片后强制切换上下文
  - 优点：保证进程**响应能力** responsiveness，**适配用户端需求**（响应能力比效率重要）
  - 缺点：平均等待时间、平均周转时间、上下文切换次数都表现不好
  - 时间片长度过长时退化为 FCFS，过短时导致大量上下文切换开销
- 优先级调度 priority scheduling：**当前采纳的方案之一**
  - 思想：每个进程赋予调度优先级（进程本身重要性，进程对各类资源的需求情况，CPU 和 I/O 突发时间）
  - 缺点：**低优先级进程可能饥饿**
    - 解决方案：优先级老化 aging，**逐渐提高等待进程的优先级**
- 多级反馈队列调度：**实际广泛应用的方案**
  - 思想：进程优先级固定，被**永久分配**到对应优先级队列中，不同优先级队列采用不同算法调度并**允许优先级抢占**
  - 问题：低优先级队列可能饥饿
    - 解决方案：**动态优先级**，进程耗尽时间片后降级，长期等待的进程升级
  - 特点：**通用**，但较复杂，可以**调整适配一个特定系统**

调度目标：策略贯彻执行（优先级调度），进程公平性（RR 调度），CPU-I/O 平衡（不调度阻塞状态进程）
- 策略贯彻执行与进程公平性，CPU-I/O 平衡存在**较大冲突**，考虑严格按优先级调度导致的 I/O 密集型任务饥饿问题
- 进程公平性与 CPU-I/O 平衡存在**小冲突**，考虑严格按时间片分配影响 I/O 密集型任务的周转时间
- 权衡方案：多级反馈队列调度

软实时/硬实时任务
- 软实时：关键进程赋予更高优先级，但**不保证在截止时限前完成**
- 硬实时：进程必须在规定截止时限前完成

实时 CPU 调度
- 要求：响应性（立即对实施进程作出响应），允许抢占并**采用基于抢占的优先级调度算法**
- 延迟控制：中断延迟（确定中断类型、保存当前进程状态的时间），分派延迟（分派器抢占当前进程并释放其资源的时间）
  - **减少中断被禁用的时间**
  - 使用**抢占式内核**
- 频率单调调度 rate monotonic
  - 思想：进程优先级与其频率成正比
  - 局限性：**不能保证一组进程绝对能被成功调度**
- EDF (Earliest Deadline First)
  - 要求：**进程声明截止时限**，不要求进程是周期性的或 CPU 突发时间恒定

对称多处理 SMP 系统调度
- **处理器亲和性**：让一个进程尽可能长时间地在同一个处理器上运行，进程迁移带来大量开销（CPU 核缓存失效和填充）
  - 软亲和性：负载极度不均时允许进程迁移
  - 硬亲和性：进程必须始终在同一个处理器上运行
- 非统一内存访问 NUMA 架构：进程被调度到**离其数据所在内存最近**的 CPU 运行
- 负载均衡
  - 推迁移 pull migration：将进程从繁忙的 CPU 迁移到空闲的 CPU

调度算法评估方案
- 确定性建模：采用**预设固定**的进程输入
- 排队模型：使用**概率分布**建模进程到达和 CPU-I/O 突发时间
- 仿真与实现：使用**真实系统**运行时记录的数据驱动仿真器

### 课件第 7 章：内存管理
用户空间内存：分段存储 segmentation
- 从低址到高址：代码段、数据段/BSS 段、堆、栈
- 32 位系统的寻址空间：按字节寻址，**进程**最大内存容量 4GB

代码段
- 存放内容：代码、**常量**
- 要求：只读，对其进行修改会触发段错误

数据段/BSS (Block Started by Symbol) 段
- 数据段存放内容：**非零初始化**的全局/静态变量
- BSS 段存放内容：**未初始化/初始化为 0** 的全局/静态变量
- BSS 段作用：记录未初始化变量的**符号列表**和对应的**大小**
- 编译器限制：底层实现要求数组大小为 32 位有符号整数（**数组大小小于 2GB**，需要考虑单个元素大小和元素数量）
- 32 位 Linux 系统的用户地址空间大小约为 **3GB**

栈
- 存放内容：局部变量、**函数参数**、**程序参数**（运行程序的命令中各个参数）、**环境变量**
- main 函数退出行为：控制权交给 C 运行时库 C library，最终调用 `exit()` 系统调用
- 局部变量大小超过系统预设的栈大小（**通过 `ulimit -s` 查看**）时触发段错误
- 任何函数都可以**对整个栈进行读写**，而不仅限于当前函数的栈帧
- 避免递归调用导致栈溢出：减少参数数量、减少局部变量数量、减少递归调用层数、使用全局变量

堆
- 特性：大小和生命周期在编译时未确定
- `malloc()` 底层行为：先尝试在空闲块链表中寻找合适的块大小（取决于具体的**适应算法**），再尝试发起 **`brk()` 系统调用**
- `free()` 释放**堆末尾**的块：发起 `brk()` 系统调用，将空间**归还给操作系统**
- `free()` 释放**堆中间**的块：将空闲内存块串联成链表，不归还给操作系统
- 若给 `free()` 传入错误的地址（包括但不限于非 `malloc()` 返回地址），会导致**错误识别 Header 位置**，破坏整个堆结构，**导致段错误**

隐式空闲链表：通过块 Header 中的大小信息遍历整个堆空间
- 块合并 coalescing：释放块时，尝试将当前块与下一空闲块合并形成大空闲块
- 与上一空闲块合并：在块后添加**边界标记/脚部** boundary tag/footer

内存分配匹配策略
- 首次适应 first fit：**从堆头开始**选择第一个足够大的空闲块
  - 特点：速度快，在堆头可能留下小外部碎片
- 循环首次适应 next fit：**从上次搜索结束的地方开始**选择第一个足够大的空闲块
  - 特点：比首次适应更快，但内存利用率比首次适应更差（**整个堆可能不再存在大块内存**）
- 最佳适应 best fit：选择满足要求的最小空闲块
  - 特点：**有助于减少外部碎片**（保留大空闲块），但**查找时间长**，且容易留下**极小外部碎片**
- 最坏适应 worst fit：选择最大空闲块
  - 意图：让剩下的空闲部分尽可能大
  - **实际效果不佳**

碎片
- 外部碎片：采用**内存紧缩** compaction，移动已有数据以整合空闲内存
- 内部碎片：有效载荷小于分配的块大小，无法被系统分配给其它程序

显式空闲链表：**在空闲块内部隐式维护指针**，将空闲块连接成双向链表
- 效果：分配器**只需要遍历空闲块**，不需要遍历已分配块
- **边界标记**仍然用于相邻块合并

分离空闲链表
- 思想：按空闲块大小维护若干链表
- 使用：按块需求搜索对应链表并进行切分，未找到合适块时查找下一个链表
- 效果：**近似最佳适应**

伙伴系统：块大小总是**按 2 的幂进行切分**

OOM (Out Of Memory)：**在向申请内存真正写入数据之前，只在虚拟地址空间中分配一段记录**而非真实物理内存

段错误场景
- 写入代码段
- **读**写未分配（堆栈）/不可使用区域

虚拟内存
- 背景：进程大小希望超过物理内存大小
- 解决方案：把进程当前不使用的部分留在硬盘交换空间中，把运行部分调入物理内存
- 内存管理单元 MMU (Memory Management Unit)：**内置在 CPU 中**，**执行地址转换**
  - **指令中总是指示虚拟地址**，即使指令位于物理内存中
- 优势
  - 进程地址空间隔离，**不同的进程可以使用相同虚拟地址**
  - 通过虚拟地址**实现内存共享**
  - 支持**内存动态增长**，进程内存不需要在物理内存中连续分布

内存管理单元实现：**分页**
- 背景：32 位系统中地址大小固定为 4 字节，需要缩小查找表大小
- 地址结构：虚拟**页地址** 20 位，页内偏移量 12 位
- 性质
  - **相邻虚拟页不保证映射到相邻物理页**
  - 一个页只能分配给一个进程，忽略内部碎片以**保证大映射粒度**

页表
- 需要维护的信息：虚拟页到页框（物理页）的**映射关系**、页面**权限信息**、页面**是否位于内存**
- **每个进程都需要一个独立页表**，因为每个进程都有自己的虚拟地址空间
- CPU 抛出段错误的场景：**访问未分配物理页的虚拟地址**，向只读页面写入数据，**执行不可执行的页面**
- 需要解决的问题：大规模页表存储，提高内存访问性能
  - 大规模页表存储：采用多级页表（对应进一步**切分页地址段**）、哈希页表、倒排页表（基于物理页建立映射关系）
  - 提高内存访问性能
    - 大页技术（减少页地址段长度），带来内部碎片，且**难以执行内存去重**（难以找到完全相同的大页）
    - TLB 缓存技术：速度快（**指令流水线一部分**），容量小
    - 有效内存访问时间：取决于 TLB hit rate、内存访问时间（注意**页表也位于内存中**）

段表
- 特点：**按照程序逻辑功能划分**（每个段的权限是统一的），**无内部碎片**
- 缺点：**段长度不一**，高频换入换出会产生严重**外部碎片**，访问时必须显式给出段号和段内偏移

请求调页 demand paging
- 定义：只首先分配虚拟地址范围，在真正访问内存时才在物理内存中分配对应空间
- 过程：访问非法虚拟页时触发 **page fault 中断**，中断服务例程在物理内存中分配物理页并**更新页表条目**，之后**重新执行同一条指令**
- 物理页面已满：选择一个已映射虚拟页换出到磁盘交换空间（更新虚拟页状态为 invalid），把对应物理页分配给新虚拟页

交换分区
- 定义：在永久存储设备上预留的空间（Linux 使用独立磁盘分区，Windows 使用隐藏的文件 `pagefile.sys`）
- 旧有约定：交换区大小至少与物理内存大小相同
- **通过请求调页运行大进程**
- 系统支持的最大进程大小：物理内存大小+交换空间大小<strong>-内核内存大小</strong>

写时复制 COW (Copy On Write)
- 过程
  - 子进程与父进程共享相同的内存物理页，**页面权限设为只读**
  - **父进程或**子进程尝试修改页面时触发 page fault，复制一个新物理页给该进程用于修改

请求调页性能衡量
- 主要耗时点：page fault 处理例程、从外存读入页面、**重新启动进程**
- **有效访问时间** $(1-p)t_{m}+pt_{pf}$（$p$ 是缺页率 page fault rate，$t_m, t_{pf}$ 分别是内存访问时间和缺页处理总时间）

请求调页的优势：允许**内存超配** over-commitment，支持**大型进程**或**多进程并发运行**

页面置换算法
- 最优算法：替换当前**在未来最长时间不会被使用**的虚拟页面
- FIFO：替换当前**最早被换入**的虚拟页面
- LRU (Least Recently Used)：替换**上次访问时间最久远**的虚拟页面
  - 维护每个页面的年龄 age，当前访问页面的 age 重置为 0，其余页面 age 增加
  - 实现方案：计数器法（**内存页面多**时较慢），栈法（双向链表，**最新访问的页面移到表头**，**取表尾淘汰**，**频繁内存操作**时较慢）
- **第二次机会算法**：LRU 近似
  - 思想：访问过的页面**引用**位置 1；置换时**若发现引用位为 1 的页面则清零**，否则将其用于置换
  - 高效实现方案：**循环队列**
  - **所有页面都访问过时，退化为 FIFO 算法**

Belady 异常
- 背景：页框越多，物理内存总量越大，系统运行速度（由 page fault 次数反映）更快
- 定义：**增加物理页框数量**时缺页次数反而增加的现象
- **堆栈算法**：对**任意页面访问序列**，**任意时刻**具有 n 个页框时的页面集合一定是具有 n+1 个页框时页面集合的**子集**

多进程页框分配
- 空闲页框列表
- 进程分配页框数量上下限
  - 上限：系统物理页框总量
  - 下限：限制缺页率，避免系统发生抖动 thrashing；计算机架构决定**某条指令涉及的所有虚拟地址必须能同时位于内存中**
  - 若进程分配的页框数量低于下限，则操作系统必须将其**挂起**
- 分配算法
  - 全局/局部置换：进程可以从**所有页框**中选择一个替换/进程只能从**分配给自己的页框**中选择一个替换
  - 平均分配：每个进程分到的页框数相同
  - 按比例分配：每个进程**按虚拟内存大小占所有进程总大小的比例分配**
  - 基于优先级的方案：分配比例取决于进程大小和它的**优先级**，**高优先级进程可能抢占**低优先级进程的页框

**抖动** thrashing
- 定义：**进程分配页框数量不足**时，发生高频缺页异常 page fault，导致**页面置换时间高于执行程序代码的时间**
- 场景：**多道程序程度过高**（CPU 利用率先升后降）
- 解决方案
  - 局部置换或优先级置换
    - 优点：不会引起其它进程抖动
    - 局限性：该进程高频缺页中断，导致**调页设备等待队列变长**，**缺页中断的平均处理时间增加**，**影响其它进程的有效访问时间**
  - **工作集模型**
    - 工作集：**最近 $\Delta$ 次页面访问中某个进程所访问的页面集合**
    - 若**所有进程工作集总和大于系统页框数量**，则会发生抖动，此时需要**挂起部分进程**
    - 用途：估算所有进程的页框需求总量
  - **缺页频率策略**：缺页率过高时增加进程分配的页框数量，缺页率过低时减少进程分配的页框数量

内核内存分配
- 场景：内部数据结构**大小多变**且**普遍较小**，常常**需要连续内存**
- 分页算法会带来**内部碎片问题**
- 解决方案：伙伴系统+Slab 分配器
  - 伙伴系统：分配固定 2 的幂次大小的连续内存区域，利于空闲内存空间合并
  - Slab 分配器：将连续内存区域分别**切分成不同固定大小的小区域**，分配给对应的内核数据结构

内存映射文件
- 定义：将文件关联到虚拟地址空间的一部分
- 过程：首次访问通过缺页异常将文件调入内存，此后**读写操作变为常规内存访问**
- 优势：**减少系统调用次数**，提升性能，允许**多个进程映射到同一份文件**（**进程间通信**的方式之一）


### 课件第 8 章：大容量存储
固态硬盘结构
- 磁道 track，扇区 sector，柱面 cylinder
- 访问方式：**寻道+旋转**
  - 寻道时间：将磁头转动到目标柱面
- 存储布局：恒定线速度 CLV (Constant Linear Velocity)，恒定角速度 CAV (Constant Angular Velocity)
  - （磁头）恒定线速度：每个磁道的存储密度相同，**外侧磁道的扇区数量更多**
  - （磁头）恒定角速度：**盘片转动速度不随磁头位置变化**，**内侧磁道扇区数量更多**（数据密度更高）
  - CLV 典型设备：光驱
  - CAV 典型设备：机械硬盘
- 地址映射：柱面号→磁道号→扇区号
- 磁盘管理的目标：磁盘格式化、坏块管理

磁盘格式化
- **低级格式化/物理格式化**
  - 划分扇区
  - 扇区内填充数据结构：表头 header、表尾 trailer（扇区号+**纠错码**）；数据区
  - 在磁盘**出厂**时完成
- **构建文件系统**
  - 磁盘分区：分为若干柱面组
  - **高级格式化/逻辑格式化**：在每个分区中存储文件系统数据结构
  - I/O 优化：以簇为单位进行，以**增加顺序访问比例**
- 原始磁盘
  - 不使用任何文件系统，直接将磁盘作为数组使用
  - 程序可**完全控制数据在磁盘上的绝对位置**

坏块管理
- 维护坏块列表（**在低级格式化期间初始化**），**预留备用扇区**
- 扇区预留/转发：使用某个备用扇区替换坏扇区
  - 问题：干扰磁盘调度算法执行
  - 解决方案：每个柱面上都**预留若干扇区**，**预留备用柱面**
- **扇区滑移** sector slipping：将坏扇区之后的所有正常扇区向后平移一个扇区，空出的扇区存放坏扇区中的数据

磁盘调度
- 原因：磁盘请求顺序影响访问性能
- **定义**：在等待队列中选择下一个执行的请求，以最大程度**减小寻道时间**
- FCFS：公平，但服务速率不是最优
- SSTF (Shortest Seek Time First)
  - 思想：选择执行具有**最短寻道时间**的请求（**最靠近当前磁头所在柱面**的请求）
  - 局限性：可能导致**请求饥饿**问题
- SCAN：**电梯算法**
  - 思想：从单端柱面开始扫描到另一端柱面，反向**扫描并返回**
  - 局限性：**磁头在磁盘一端时，磁盘另一端的请求等待时间较长**
- C-SCAN (Circular SCAN)
  - 思想：从单端柱面扫描到另一端柱面，反向**直接返回**
- LOOK
  - 思想：靠近磁盘一端时，**若前方没有请求就直接返回**
- C-LOOK：单向扫描，若前方没有请求就直接返回另一端的新请求

**影响磁盘性能的因素**
- 请求数量与类型
  - 低负载时不同调度算法差异有限
  - 读请求注重**延迟**，写请求注重**吞吐量**
- 文件分配方法
  - 连续分布时磁盘进行顺序 I/O，延迟最低
- 目录和索引块的位置
  - **元数据块与数据块的相对位置**影响数据读取的总延迟

操作系统实现磁盘调度的设计原则
- 满足 OS 定义的**优先级**
- 模块化设计：将磁盘调度算法设计为操作系统的模块，**易于更换磁盘调度算法**
- OS 默认采用的磁盘调度算法：**SSTF/LOOK**

固态硬盘 SSD (Solid State **Drives**)
- 分类：**NAND 闪存**、NOR 闪存
- NAND 闪存分类：SLC (Single-Level Cell)，MLC (Multi-Level Cell)
  - SLC：每个存储单元存储 1 位数据
  - MLC：每个存储单元存储 **2/3 位数据**
- 原子操作：编程 program（**0→1**），擦除 erase（**1→0**）
  - 注意编程操作与擦除操作的数值变化方向！
  - 无法直接覆写新数据
  - 随着编程-擦除周期（P/E 周期）数增加，**存储单元可靠性下降**
- 结构层级关系：芯片 package→晶圆/颗粒 die/chip→平面 plane→块 block→页 page
  - 擦除最小单位为**块**，编程最小单位为**页**
- SSD 核心组件：芯片、**控制器**、**内存**（位于 SSD 上的**独立 RAM**）
  - 内存存储闪存转换层 FTL，**FTL 保存逻辑地址到物理地址的映射表**
  - 内存**存储频繁修改的临时数据**，可**减少闪存磨损**
  - 内存**辅助垃圾回收过程**，搬运整理数据

SSD 操作
- 读写：按页为单位（**4KB**）
- 擦除：按块为单位（64/128 页），把所有位都变为 **1**，**速率远慢于读写**
- 删除：**标记该页为无效页**
- 覆写：数据只能写入到干净的页（已被擦除的页）
- 软件层面提升写入性能：**地址映射** address mapping
- 页面状态转移周期：free/clean →(write)→ valid →(update)→ invalid →(erase)→ free/clean

闪存转换层 FTL (Flash Translation Layer)
- 功能：**地址映射**、**垃圾回收**、**损耗均衡**
- 地址映射：扇区映射，块映射，混合映射，日志结构映射
  - 扇区映射：每个逻辑扇区号对应一个物理扇区号
    - 缺点：**映射表规模大**，消耗 RAM 空间
  - 块映射：逻辑扇区偏移量与物理扇区偏移量保持一致
    - 优点：缩小映射表
    - 缺点：易引发频繁擦除操作（扇区映射固定，**无法更换物理扇区写入**）
  - 混合映射：先进行块映射，再在块内进行扇区映射
    - 优点：映射表体积小，减少擦除操作量
    - 缺点：**查找某一页的时间更长**
  - 日志结构映射：**数据块采用块映射**，**日志块采用扇区映射**
    - 日志块**接收更新数据写入**
    - 内存中通过 BMT 管理数据块，通过 SMT 管理日志块
    - 日志块写满后**通过垃圾回收将日志块与数据块进行合并**
  - 映射策略权衡：扇区映射适合随机读写，块映射适合顺序读写，**日志结构映射适合大顺序读写+小随机读写**

垃圾回收 garbage collection
- 思想：选择可用块，将有效数据写入新块，再擦除原有块
- 算法：贪心（选择**无效页面最多**的块回收），随机（随机选择一个块回收）
- 优化：冷热数据，将热数据（频繁修改）与冷数据（长期不修改）分开存储，**避免在垃圾回收时反复迁移冷数据**

RAID (Redundant Array of Independent Disks) 分级
- RAID 0：块级条带化，无冗余
  - 思想：将数据分散写入多个磁盘
  - 优点：提高**数据传输速率**（可以**同时读写多个磁盘**）
  - 缺点：**无可靠性**，无法抵抗磁盘故障
- RAID 1：数据镜像
  - 思想：将完全相同的数据写入多个物理磁盘
  - 优点：极大**提高可靠性**
  - 缺点：存储成本高，**存储效率低**
- RAID 01：先条带化再镜像
  - 思想：将数据分散写入一个磁盘组中所有磁盘，磁盘组间写入数据相同
  - 特点：存储效率与 RAID 1 相同，一个磁盘损坏导致**该磁盘组失效**
- RAID 10：先镜像再条带化
  - 思想：将相同数据写入磁盘组中所有磁盘，不同磁盘组写入不同数据
  - 特点：存储效率与 RAID 1 相同，一个磁盘损坏可直接通过镜像盘修复
- RAID 4：引入专门奇偶校验盘
  - 思想：使用**专用校验盘**存储其它磁盘相同条带上的奇偶校验数据（**异或和**）
  - 缺点：**校验盘读写负荷高**
  - 单个数据块更新：RMW (Read-Modify-Write)，读 2 次（老数据和老校验）+写 2 次（新数据和新校验）
  - 多个数据块更新：RRW (Read-Reconstruct-Write)，**读出所有条带的最新数据**计算得到新校验数据
- RAID 5：每个盘一个校验条带
  - 特点：**性能、容错能力好**（数据条带化，**允许任意一块磁盘丢失**），**容量、存储效率高**（共损耗一块盘的容量）
  - 问题：仍然存在**奇偶校验码高频更新**的性能瓶颈
- RAID 6：每个盘两个校验条带
  - 思想：使用异或和和伽罗瓦域代数运算实现双重校验
  - 特点：**允许丢失两块磁盘**
  - 问题：**校验更新开销更大**，写入性能比 RAID 5 更差
- SSD RAID 的问题：校验更新同时影响读写性能和 **SSD 寿命**（带来额外的 I/O 与垃圾回收开销）
- 传统校验日志
  - 在 SSD RAID 5 中只更新数据块，同时在更高性能的日志设备 log device 中存储每次修改前后的数据块
  - 日志设备将满时，通过释放 flush 过程，利用旧校验块和增量更新数据计算出新校验块写入 SSD RAID 5

### 课件第 8-2 章：I/O 系统
I/O 设备分类：存储设备、传输设备、人机交互设备；块设备、字符设备、网络设备
- 存储设备：硬盘、SSD、U 盘
- **传输设备**：网卡、调制解调器
- **人机交互设备**：键盘、鼠标、打印机
- 
- 块设备：数据存储在**固定大小的块**中，如磁盘存储器
- 字符设备：以**字符流**方式传送数据，如键盘、鼠标、串口
- 网络设备：通过**套接字接口**交互

I/O 系统常见核心概念
- 端口：设备与计算机的**连接点**
- 总线：菊花链总线（串行）、共享直接访问总线（并行）
  - 扩展总线：用于连接**速度较慢**的外围设别
- 控制器：负责操作端口、总线、I/O 设备

设备附带寄存器
- data-in register：存放设备传往主机的数据
- data-out register：存放主机传往设备的数据
- status register：指示设备当前状态
- control register：主机向此寄存器写入特定位以**向设备发送控制命令**

设备与主机通信方式：直接 I/O，内存映射 I/O
- 直接 I/O：CPU 使用专用机器指令访问 I/O 端口地址空间
- 内存映射 I/O：设备的数据寄存器和控制寄存器映射到内存中，CPU 通过常规访存指令与设备交互

轮询过程
1. CPU 检查状态寄存器直到忙碌位变为 0
2. CPU 向控制寄存器写入读/写命令，向数据输出寄存器写入数据
3. CPU 设置命令就绪位
4. 控制器设置忙碌位，开始执行数据传送
5. 控制器在数据传送完成后清除忙碌位、错误位、命令就绪位

中断
- 中断线类型：可屏蔽/不可屏蔽
- 中断向量：将中断分派到对应的中断处理例程
  - 中断链：多个硬件设备共享中断号，对应的设备处理程序串为一个链表，系统逐个询问链上设备直到找到发出中断的设备并执行其处理程序

DMA (Direct Memory Access)
- 目的：解决大规模数据移动问题
- 特点：绕过 CPU，**在设备与内存之间**直接进行数据交换

DMA 工作流程
1. CPU 向 DMA 控制块（操作类型、数据量、源/目标地址）写入内存
2. CPU 向 DMA 控制器写入 DMA 控制块位置
3. DMA 控制器接管总线传输数据

内核 I/O 子系统功能
- I/O 调度
- 缓冲 buffering
- 缓存 caching
- 假脱机 spooling
- 错误处理和 I/O 保护
- 电源管理

### 课件第 9 章：文件系统
文件系统：布局、操作
- 布局：存什么，存在哪
- 操作：定义 **OS 如何处理**底层数据布局

OS 与 FS 的关系
- OS 可以支持多个 FS
- FS 可以被多种 OS 读取

FS 与存储设备的关系
- 存储设备可包含/不包含 FS，可以包含多于一个 FS
- 存储设备不了解其中存储的 FS
- OS 指示存储设备存储数据

文件系统的两个基本要素：**文件、目录**

文件系统布局：影响 FS **操作速度**、FS **可靠性**、磁盘空间管理（分配与释放）

文件的定义
- 基本定义：OS 为存储在物理设备上的信息提供的一种**统一逻辑视角**
- OS 视角：**逻辑存储单元**（一串逻辑记录），一种抽象数据类型
- 用户视角：逻辑辅存中的最小分配单位

文件要素：**文件类型**、文件属性（文件元数据）、**文件操作**
- 常见文件属性：名称、**标识符**（操作系统内部数字标识）、**类型**、位置、大小、日期时间、**保护水平**
- **文件属性取决于 FS** 而非 OS

目录：**一种文件**
- 目录是否有文件属性取决于 FS 实现，但一定有文件内容
- 路径名 pathname `home/test.txt`；文件名 filename `test.txt`
  - 路径名在文件系统中唯一
  - 文件名在文件系统中不需要唯一，但**在所在目录下唯一**
  - OS 内核将路径名转换为存储设备上的一组数据地址，**路径名起到 key 的作用**
- 使用路径名定位一个文件：提供路径名→**取目录文件→读目录文件**→取子目录文件→读子目录文件→…→取文件
- 创建文件：等效于**更新目录文件**
  - `touch` 只修改目录文件，**不为文件内容分配任何空间**
- 目录文件操作：创建目录 `mkdir`，新增条目 `cp, mv, ...`，删除条目 `rm`，**删除目录 `rmdir`**

操作系统需要提供的文件系统操作
- 创建、删除
- 写入、读取
- **重定位/定位** reposition
  - 文件寻道/指针移动，不涉及 I/O
  - **随机访问**使用
- **截断** truncate
  - **仅保留属性**

打开文件表：操作系统维护，进程级/系统级

FILE 结构体
- 主要内容：**文件描述符** file descriptor，**缓冲区** buffer
  - 文件描述符可使用 `fileno()` 查看
- `fopen()` 创建，位于动态分配内存区（类似 `malloc()` 过程）

**打开文件过程**
1. 进程提供路径
2. 操作系统**通过 FS 在磁盘中**查找文件属性
3. 磁盘返回文件属性，OS 将其加载到内核打开文件表
4. OS **将文件属性关联到一个文件描述符**（基于**进程**打开文件表）
5. OS 将文件描述符返回给进程
- 上述逻辑**在所有 OS/FS 上相同**

文件描述符本质：**数组下标**，用于定位本进程打开的文件
- 不同进程可以通过各自的文件描述符指向内核中同一个文件结构
- 不同进程打开同一个文件时，在内核打开文件表中**留下两个独立条目**（读写模式、文件指针不同）
- **两个独立条目指向同一个 inode 结构**

`read()` 系统调用执行过程
1. 检查文件指针，**判断是否到达文件末尾**
2. 将读取指令下发给磁盘
3. 磁盘读出目标数据块，**送入内核缓冲区**（kernel cache）
4. 内核将数据从内核缓冲区**写入用户空间缓冲区**

`write()` 系统调用执行过程
1. 将数据**写入内核缓冲区**
2. 更新内核中该文件元数据
3. **系统调用返回**
4. 缓存数据**定期异步写入磁盘**

内核缓冲区缓存的作用
- 提高读取性能、写入性能
- 代价：**强制重启计算机导致损失数据**，弹出磁盘之前需要**强制刷盘**（点击“弹出”）

FS 管理存储设备的**基本要求**
- 写入数据可被检索
- FS 操作尽可能高效
- 删除文件后释放对应空间

文件系统分配方法
- 连续分配
  - 特点：每个文件分配连续的地址空间，**相邻文件地址范围紧邻**，通过**文件目录表**维护
  - 优点：通过目录**易于定位文件**
  - 缺点：**不容易寻找空闲空间**（必须遍历文件目录表），存在**外部碎片**和**文件增长**问题
  - 用途：只读文件系统（光盘，ISO9660）
- 链式分配
  - 特点：存储空间切分为等长块，文件按块填入空闲位置，目录表**维护文件块号范围**
  - 缺点：**难以用目录表中的范围模拟链表**
- 改进链式分配
  - 特点：每个块首 4 字节维护下一个块号索引，目录表**维护首块号**
  - 额外需求：目录表需要**存放文件大小**（最后一个块可能未填满），需要维护空闲块链表（例如存储首空闲块号）
  - 优点：无外部碎片问题，文件大小可变，空闲块管理易实现
  - 缺点：**随机访问性能差**（$O(n)$ 时间复杂度），**内部碎片**问题
- **FAT 表方案**
  - 特点：在链式分配基础上，改为使用专门**集中**的 **FAT 表**（**位于磁盘**）维护文件块的邻接关系
  - 只有对 FAT 表采用**数组实现**才能解决随机访问问题
  - 缓存改进：在内核中保留 **FAT 表缓存**

FAT 文件系统
- **块称为“簇”**
- FATx 代表**簇地址位宽为 x** 的 FAT 文件系统（如 FAT12/16/32）
  - 簇地址位宽决定文件系统可以管理簇的最大数量（$2^x$）
- 方案评估
  - **FAT 表必须在内存中缓存**，才能达到较好性能
  - 可以不将完整的 FAT 表全部存入内存，为此牺牲一定的数据块查找性能

Index Node 方案
- 最初想法：对**每个文件**维护一个 Index Node；**长度可变**，不利于存储和文件大小变化
- 思想：采用固定大小索引节点+多级间接寻址方案
  - inode 中包含直接块指针、一级间接块指针（指向填满数据块物理地址的间接块）、二级间接块指针、三级间接块指针
  - **间接块也存放在数据块区域**
- 文件最大大小：取决于块大小、**指针大小**
  - 间接块数量取决于块大小、指针大小、**文件大小**
- 目录文件下存放每个文件的 inode 编号
- 文件系统布局：**索引节点表**、**空闲块链表**、**根目录**、数据块区域
- 优势：易于实现 inode 部分缓存
- 额外开销：在必要时引入间接块，采用固定大小 inode **占用更多存储空间**

**存储设备中主要存储对象**：**根目录**、**文件属性**、**空闲空间管理**（空闲块链表）、**数据块管理**（目录表，FAT，inode）

Index Node 方案下子目录的存储：与根目录类似，**对应 inode 中存储一个映射表**（条目是目录项=文件名+inode）

文件系统在磁盘上的存储布局
- 主要存储内容：根目录、索引节点、数据块、空闲空间信息
- **文件系统元信息** file system information：位于**磁盘上固定位置**
  - **主要内容**：根目录位置、数据块管理信息位置和大小、块大小、已分配块和空闲块数量
  - 不能直接硬编码到 OS 内核中，不同存储设备有不同需求（取决于**硬盘大小**、分区格式），只能将它们保存在存储设备上
  - FAT/NTFS 系统上称为启动扇区，Ext 系统上称为超级块 superblock

磁盘分区
- 原因：**限制文件系统大小**，在单个磁盘上**支持不同文件系统**
- 主要结构：引导代码（**指示引导和启动操作系统的分区**），分区表（每个分区的**起始扇区**、分区**长度**、分区**类型**）
- 优势：**性能提升**（小文件系统效率更高），**多系统共存**，分别**存放不同类型数据**

主引导记录 MBR (Master Boot Record)
- 大小固定为 **512 字节**
- 主要组成：**引导代码**、分区表（64 字节，每个分区表项固定占用 16 字节，因此最多创建 4 个分区）、有效标志（2 字节，`0xAA55`）

### 课件第 10-1 章：FAT32 文件系统
目录条目：固定占用 **32 字节**
- 第 0 字节存储文件名第 1 个字符，若为 **`0x00/0xe5` 代表该条目未分配**
- 第 1—10 字节存储文件名 2—8 字符和 **3 字符扩展名**（不包括扩展名前的句点）
- 第 11 字节存储文件属性
- 第 20—21 字节存储起始簇号高 2 字节（FAT16/12 文件系统固定为 0，**固定采用小端序**存储）
- 第 26—27 字节存储起始簇号低 2 字节（**固定采用小端序**存储）
- 第 28—31 字节存储文件大小，因此**文件最大为 4GB**
- FAT32 系统引入 **LFN** 代替 8+3 命名规范，通过在原目录项**之前倒序**（*最后一个目录项的下标最小*）添加若干额外目录项来拼接并存储完整文件名
  - 对于长文件名文件，**按特定规则生成 8+3 短文件名**存入第 0—10 字节
  - 每个 LFN 目录项存储 13 个字符（**包括扩展名前句点**），依次位于 1—10 字节、14—25 字节、28—31 字节
  - LFN 目录项的文件属性始终为 **`0x0F`**，同时第 13 字节是校验和
  - LFN 第 0 字节存储文件名序列号，**最后一个 LFN 条目的值按位或 `0x40`**

FAT 目录项的**三个核心存储要素**：内容起始位置（**起始簇号**）、内容结束位置（**文件大小**）、**文件属性**

文件读取
1. 从根目录—子目录定位目标文件的目录项，得到文件**起始簇号**
2. 通过 FAT 表链式追踪读取文件各个簇，直到读到在 FAT 表中后继为 EOF 的簇

文件写入
1. 定位到文件最后一个簇
2. 从非满簇开始向后追加写入
3. 根据 **FSINFO 中存放的下一个空簇信息**，分配新空簇用于写入
4. **期间动态更新** FAT 表（**2 个**）和 FSINFO 信息
5. 写入完成后，在文件目录项中**更新文件大小信息**

FSINFO 的维护
- 循环、下一可用查询：**从当前被分配的簇开始**，循环向下寻找下一个空闲簇，簇号填入 next free cluster 域

文件删除
1. 更新 FAT 表和 FSINFO
2. **更新文件目录项**第一字节为 `0xe5`
- 并**没有真正从磁盘中抹去所有文件内容**
- 如果要彻底删除文件，需要额外的保护措施

恢复误删文件
1. 立刻**切断计算机电源**
2. 尝试根据 FAT 表残留信息和目录条目项中保留的首簇号推出原文件占用的各个簇（考虑簇分配的下一可用原则）

### 课件第 10-2 章：Ext2/3 文件系统
文件系统总体结构
- 文件系统分为若干块组 group
- 每个块组内分为**超级块** superblock，**块组描述符** GDT（存储位图、inode 表等的位置信息），**块位图** block bitmap（追踪数据块使用情况，1 代表已使用），**inode 位图**（追踪 inode 节点分配情况），**inode 表**（文件元数据、直接块/间接块指针），数据块区

文件系统设计思路
- 每个块组内 superblock 完全相同，**互为备份**，其中 group 0 的 superblock 称为 primary superblock，其余 superblock 称为 backup superblock
- 块组内 **inode 与对应数据块距离更近**（相比只使用单个块组），**提高数据访问效率**

超级块存储内容
- inode 总数
- 数据块总数
- 保留块数量（预留给 root）
- 空闲块数量
- 空闲 inode 数量
- 首块地址
- 单个数据块大小

块位图大小固定，因此**文件系统（块组）的块数量固定**

inode 位图的大小固定，意味着**文件系统（块组）能容纳的文件总数固定**

最大文件大小影响因素：inode 中文件大小表示域位宽、**块大小和间接数据块指针结构**

链接文件
- **硬链接** hard link：指向**已存在文件**的链接，**使一个文件拥有多个路径名**
  - **硬链接文件与目标文件共享同一个 inode**
  - 特殊硬链接：`.` 是指向当前文件的硬链接，`..` 是指向上级目录的硬链接
  - 用户只能创建指向文件的硬链接，不能创建指向目录文件的硬链接（**防止目录树成环**）
- 目标文件 inode 中维护 **link count 域**指示指向该文件的目录条目数
  - 文件被创建时，link count 值为 1；**目录被创建时，link count 值为 2**
  - 删除一个文件的系统调用：`unlink()`，将文件的 link count 减少 1
  - 文件 link count 为 0 时，**由内核回收**文件的数据块和 inode
- **符号链接** symbolic link：存储**指向目标文件的路径字符串**的文件
  - 符号链接文件对应新 inode
  - 若路径长小于 **60 字节**，直接存储在原目录项的 12 直接块指针+3 间接块指针域内（每个指针 4 字节，每个字符 1 字节）；否则分配一个新数据块存储路径

缓冲区缓存：依据**局部性原理**
- 缓存内容：近期被读取/写入的**数据块**、目录文件、inode
- 类型：页面缓存、目录项缓存、索引节点缓存
  - **即使文件关闭，条目仍然留在缓存中**，以便文件再次被打开时更快响应
- 调度算法：**LRU**
- 预读 readahead
  - **异步**系统调用 `readahead()`，用于**阻塞**某线程以将文件内容按需读入缓冲区缓存
  - 工作原理：在读取某个数据块时，**依据文件读取模式、读取历史判断**是否将后继数据块提前读入内存
  - 优势：**降低磁头寻道成本**
  - 对于 SSD，顺序读取同样快于随机读取，因此预读也有助于提升 SSD 读取速率
- 带缓冲区缓存的写入操作：写直达/写回
  - 写直达：数据同时写入磁盘和缓冲区缓存，**数据一致性高**，但**性能较低**
  - 写回：数据只写入缓冲区缓存，之后按需写入磁盘，**速度快**但**存在数据丢失风险**

日志 jornaling：**Ext3 文件系统引入**
- 现有解决方案不足
  - 缓存可能导致系统不一致性，缓存数据可能丢失
  - 磁盘只提供单次单扇区的原子写入，**不能保证多个扇区同时写入的原子性**；实际上写入操作通常需要修改多个扇区（inode、数据块、块位图修改）
- 思想：在实际写入之前，**将操作步骤记录在日志区**
  - 若写入日志时系统崩溃，仍保证原数据安全
  - 若写入数据时崩溃，可**根据日志恢复未完成工作**
- 存放位置：**超级块与 0 号块组之间的日志区**
- **日志布局**：日志开始块 TxB（**包括事务标识符 TID**）—日志正文（元数据+数据，inode/bitmap/data block）—日志结束块 TxE（**包括 TID**）
- 日志写入策略
  - 逐个写入：以功能块为单位顺序发送日志写入请求，速度慢（磁盘寻道和旋转延迟）但安全
  - 一次性写入：以完整日志为单位发送日志写入请求，速度快但可能造成日志失效（TxB、TxE 可能先于元数据+数据写入完成，造成**伪有效日志块**）
  - **写入-提交** write-commit：**先就除了 TxE 以外的所有部分发送写入请求**，再就 TxE 发送写入请求（称为一次提交 commit），可以**保证 TxE 写入的原子性**
- 日志系统的数据写入流程：日志写入—日志提交—检查点 checkpoint（写入数据全部落盘）
- 数据恢复
  - 崩溃发生在 commit 之前：直接跳过本次数据修改
  - 崩溃发生在 commit 之后、checkpoint 之前：重放 replay 本次事务（称为重做日志 redo logging）
- 日志空间有限问题
  - 日志填满的后果：重放时间过长，无法追加新事务
  - 解决方案：**循环**日志 circular log+日志超级块（记录日志元数据，日志起止位置、当前写入位置）

元数据日志 metadata journaling
- 日志方案的局限性：数据区共写入两次
- 改进：在日志中只记录元数据，**数据块不写入日志**
- 写入模式：回写、有序
  - 回写模式：数据块写入和日志提交无先后顺序
    - 问题：日志提交但数据未写入，造成元数据指向垃圾数据，**文件损坏**
  - **有序模式**：**先写入真实数据，再提交日志**
    - 写入时序：数据写入、日志元数据写入（**可并行**）→日志提交→元数据 checkpoint→日志释放

虚拟文件系统 VFS (Virtual File System)
- 本质：文件系统抽象层
- 功能：透明、统一地支持多种文件系统，**定义一套文件系统接口**，由具体的文件系统实现
- 对于一个文件系统不支持的操作，将对应函数指针设为 `NULL`
  - 执行空函数的策略：返回错误（**显式告知**该操作不被支持），不作修改（**假装操作成功**，不执行任何实际操作）
