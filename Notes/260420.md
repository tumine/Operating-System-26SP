CPU 突发的分布表现为长尾（集中在短突发段）

进程生命期：五状态表示

进程调度：从就绪队列中选取一个恰当的进程进入运行态（实际上是一种**短期 CPU 调度**）

上下文切换是开销非常大的操作

抢占式内核：单位时间内完成的任务数量更少（需要进行更多上下文切换操作），但有利于保证 CPU 的高交互性

性能指标刻画
- CPU 利用率：由于任务负载不均衡，通常在 40% 到 90% 之间，典型值在 60% 到 70% 之间
- 吞吐
- 周转时间：从任务提交到结束的时间
- 等待时间：一定程度上刻画了系统中存在的冲突情况（资源访问上的冲突）
- 响应时间：代表系统的综合性能
  - 尾时延：看第 50/90/99 分位的响应值
  - 可能出现平均时延很好，但少量请求出现高时延的情况（长尾）

调度算法
- 输入：进程及其相关联的特性
- 输出：这些进程执行的顺序，**性能的分析**

FCFS：按任务到达先后顺序执行
- 性能分析：基于甘特图
- 可以保证资源利用率，但平均等待时间、周转时间**对输入序列非常敏感**（性能受到任务到达顺序的影响）
  - 容易被“大任务”阻塞
- 算法简单，不需要知道任务对 CPU 的需求，可以选择简单的数据结构进行维护，目前仍然被大量采用

短作业优先：CPU 需求量少的任务先执行
- 不允许抢占：当前进程执行完毕后再选择下一个进程；允许抢占：有新进程等待时也要判断是否需要抢占
  - 不允许抢占的 CPU 上下文切换开销更小
  - 允许抢占的 CPU 不看任务总体需求，看任务当前剩余执行时间（也可称为“**最短剩余时间优先**”）
  - 允许抢占，会增加上下文切换次数，但有利于进一步减少等待时间和周转时间
- 对于有相同 CPU 需求量的任务，可以采用 FCFS
- 理论上是最优的，但实际上通常**难以知道每个进程对 CPU 的时间需求**
