Ext 文件系统
- 链接文件：对同一个文件，希望有多条路径可以找到
- 硬链接：本质上是一个目录条目，指向同一个文件（inode）
  - 链接数：有多少个目录条目指向当前 inode
  - 两个特殊的硬链接：`.` 和 `..`
  - 如果一个目录条目的硬链接数很大，说明这个目录下可能有**很多子目录**
  - 一个普通文件的初始链接数为 1：其所在目录条目
  - 一个目录文件的初始链接数为 2：父目录中的目录条目、当前目录中的 `.` 硬链接条目
  - 在进行文件删除时，也要考虑多个硬链接情形的处理
- 符号链接：本质上是一个普通文件，指向一个新的独立文件（inode）
  - 符号链接文件中存放原文件的路径
  - 如果路径名长度较短，考虑把路径名放到 inode 的直接块中
- Buffer Cache：页缓存、目录文件缓存、inode 缓存
  - 通常采用 LRU 替换策略
  - 读写流程的改变：是否直接写回磁盘
- 日志 Journaling
  - 掉电时，数据可能还位于内存，尚未写入磁盘
  - 目的：利用额外的空间开销确保在系统故障恢复后仍能继续执行未完成的任务
  - 数据库中称为写前日志，文件系统中称为日志
  - 事务：一个**原子性**的任务，用于标记对文件系统的修改
  - 通过在日志中写入各条事务，可以了解系统故障前的事务执行情况
  - 方案 1：把全量数据（metadata+data）全部写入日志
    - 问题：写入一个 Transaction 块过程中发生断电，部分数据未完成写入，但整个块看起来仍然合法
    - 解决方案：Journal Commit，先把所有有效数据并行写入 Transaction 块，再完成一个原子的 TxE(Transaction End) 块
    - 问题：同一个数据块在磁盘中写入了两次
  - 方案 2：数据块只写入一次，不再写入日志区
    - 只把 metadata 写入日志区
    - 数据先写入磁盘，再执行 Journal Write/Commit
- VFS(Virtual File System)
  - 希望有抽象的文件系统层，对上提供统一的文件系统接口
  - 要求文件系统能向后兼容；对于一个实际文件系统不支持的操作，给上层进程**返回一个空指针**

存储系统
- 非结构化数据（区别于数据库等处的结构化数据）在文件系统中占比约 80%；非结构化数据长度不定，对非结构化数据的处理较麻烦
- RocksDB：对于变长数据，先排序再写入
  - 数据量大时会有比较大的排序开销
  - 在外存中使用数据量逐级增加的数据条目，内存先向小数据量条目写入并排序，小条目满时再逐级向大条目写入并排序
