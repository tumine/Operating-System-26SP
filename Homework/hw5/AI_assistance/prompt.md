问题描述：在端侧部署大模型时，权重文件一般按层载入内存并用于计算，其余权重放在交换空间中。在此过程中，希望尽可能提高每层权重加载进入内存所能完成的工作量，平衡 CPU 和 I/O 利用率，最大化系统推理和产生 token 的吞吐率。

根据下列已有的想法，在arxiv上调研相关领域的论文，总结论文中的实现方案、这些实现方案可以对已有的想法落地实现有什么启发。

现有的想法
1. 权重复用，读取一次权重同时用于多个用户请求
   1. 在端侧常常只关心一个 AI 工作
   2. 如果并发度过高，导致 I/O 利用率下降（I/O 在等待 CPU），就考虑减少并发度
   3. 若能实现，测试不同并发度下的 CPU-I/O 利用率关系
   4. 多请求下kv cache无法全部放入内存，也需要放入磁盘交换空间
2. 采用 DMA，维护两个/n 个缓冲区缓存（循环队列），每个缓存中有一层的权重信息，CPU 在计算某一层的权重时 I/O 同时写另一层权重
   1. 计算时间不稳定？考虑生产者-消费者模型，I/O 不间断地向循环队列中加载下一层的权重
3. 某个磁盘分区采用 Raw I/O，专门用于存储权重信息，绕过文件系统
